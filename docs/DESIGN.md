# family-talk 仕様書

家族専用のメッセンジャー＋通話アプリ。サーバーは自前の Ubuntu マシン上の Docker で動かし、データはすべて自分のサーバー内に置く。

- ライセンス: Apache-2.0
- 想定規模: 1インスタンス 2〜20人
- 対象: iPhone / Android / PC（ブラウザ）

---

## 1. 前提条件（確定事項）

| 項目 | 内容 |
|---|---|
| サーバー | Ubuntu + Docker Compose |
| Apple Developer Program | **使わない**（無料アカウントでの署名も使わない） |
| 必須機能 | テキスト、写真、動画、通知、通話（音声・ビデオ、1対1・グループ） |
| ストア | App Store / Google Play には出さない |

---

## 2. クライアント方式

| OS | 方式 | 理由 |
|---|---|---|
| iPhone | **PWA**（Safari の「ホーム画面に追加」） | Apple Developer Program なしで日常利用できる配布手段はこれだけ。スマホ新法による代替配布も、開発者登録と公証が必要なので使えない |
| Android | **ネイティブ APK**（Web UI を Capacitor で包む） | 全画面の着信画面、OS の通話機能との統合（Core-Telecom）、FCM による確実な通知のため。ストアを通さず直接配布する |
| PC | ブラウザ（PWA としてインストールも可） | — |

- 画面は3つのプラットフォームで **同じ Web UI コード** を使う（React + TypeScript）。
- Android ネイティブの部分は、通知・着信・通話をバックグラウンドで続ける処理だけに絞る。

### 2.1 iPhone（PWA）で実現できない事項

OS の仕様上どうにもならない。README とアプリ内の案内に明記する。

1. アプリを閉じているときや画面ロック中に、**着信画面を出して鳴らし続けることはできない**。通知が1回出るだけ。
2. 画面ロックや他のアプリに切り替えると、**通話が切れる**ことがある。通話中は画面の自動消灯を抑止して対処する。
3. 通知音は OS 標準の音だけ。
4. 通知を使うには、**ホーム画面に追加してから起動する** 必要がある。

これを補うために次の動きを入れる。

- 着信は、時間を空けて通知を最大3回送る（「〇〇さんから着信」）。
- 通知をタップすると、着信画面から始まるようにする。
- 応答がなければ、トークに「不在着信」を残す。

### 2.2 Android 配布

- APK を自分のサーバーから配る（`/download/android`）。
- Google の開発者確認制度は、2027年以降日本でも始まる予定。それまでに無料の少数配布用アカウント（最大20台まで）に登録しておく。
- FCM 用に Firebase プロジェクトを作る（無料、Google アカウントだけで作れる）。
- Google Play 開発者サービスが入っていない端末では、自前の ntfy サーバー経由の UnifiedPush に切り替える。

## 3. 機能仕様

各数値はサーバー設定（`.env`）で変更できる。ここに書いた値は既定値。

### 3.1 アカウント・メンバー

| 機能 | 仕様 |
|---|---|
| 初回セットアップ | 初めて起動したときに管理者アカウントを作る |
| 参加 | 管理者または許可されたメンバーが招待リンク／QRコードを発行する。有効期限 7日、1回限り |
| ログイン | ユーザー名＋パスワード（argon2id）。一度ログインすれば長期間ログインしたまま。パスキー（WebAuthn）にも対応 |
| プロフィール | 表示名（最大 20文字）、アイコン、背景画像、ひとこと（最大 500文字） |
| 複数端末 | 1人あたり最大 5台まで同時にログインできる。端末一覧の表示とリモートログアウトができる |
| アプリロック | 4桁の PIN または端末の生体認証（Android は生体認証、iPhone はパスキー経由） |
| 権限 | 管理者 / メンバー。管理者はメンバーの招待・無効化・削除と、スタンプの登録ができる |
| 家族一覧 | インスタンス内の全員が最初から互いに表示される（友だち追加は不要）。お気に入り、自分の画面だけで使う表示名の変更ができる |

### 3.2 トーク（ルーム）

| 機能 | 仕様 |
|---|---|
| 種類 | 1対1 / グループ / 自分用メモ（自分だけのトーク） |
| グループ | 名前・アイコンを設定できる。メンバー上限はインスタンスの人数まで。誰でもメンバーを追加・退会でき、作成者と管理者はメンバーを外せる |
| トーク一覧 | 最新順。ピン留め（上限なし）、未読数、通知オフのマーク、非表示、削除 |
| 並び替え | 受信時間 / 未読 / お気に入り |
| 全て既読 | トーク一覧のメニューから実行できる |
| 背景 | アプリ全体と、トークごとに設定できる |

### 3.3 メッセージ

| 機能 | 仕様 |
|---|---|
| テキスト | 1件あたり最大 10,000文字。絵文字（Unicode） |
| URL プレビュー | サーバー側で OGP を取得して表示する。設定でオフにできる |
| スタンプ | 管理者が画像を登録してセットにする。静止画（PNG/WebP）とアニメーション（APNG/アニメーション WebP）。家族の写真から作ることもできる |
| 返信 | 特定のメッセージを引用して返信する |
| メンション | `@名前`、`@全員`。通知オフのトークでも、自分宛てのメンションは通知する |
| リアクション | 任意の絵文字。よく使う6種類をすぐ選べるようにする |
| 送信取消 | 送信後 **24時間以内**。相手側には「送信を取り消しました」と表示し、本文と添付はサーバーから削除する |
| 編集 | 送信後 **15分以内**。「編集済み」と表示する |
| 転送 | 複数のメッセージを選んで、他のトークへ転送する |
| コピー | 全文、または一部を選んでコピーする |
| アナウンス | トークごとに最大5件を上部に固定する |
| 既読 | 1対1は「既読」。グループは「既読N」と表示し、タップすると **誰が読んだか** を表示する |
| 入力中表示 | あり（設定でオフにできる） |
| 通知なし送信 | 相手に通知を出さずに送る（未読数と既読は通常どおり） |
| 予約送信 | 日時を指定して送る。最大 30日先 |
| 検索 | トーク内をキーワードと日付で検索する。トークをまたいだ全体検索もある。写真・動画、リンク、ファイルを一覧表示する |
| 削除 | 自分の画面からだけ消す（相手側には残る） |

### 3.4 写真・動画・ファイル・音声

| 機能 | 仕様 |
|---|---|
| 写真 | 1回で写真と動画を合わせて最大 50件。画質は標準（長辺 1,280px）/ 高画質（長辺 2,560px）/ オリジナル（圧縮しない）。HEIC は受け取ったときに JPEG/WebP に変換し、原本も保存する |
| 位置情報 | 写真の EXIF から位置情報を必ず取り除く（オリジナルでも取り除く） |
| 写真の編集 | 送る前にトリミング、回転、手書き、文字入れ、モザイクができる |
| 動画 | 長さの制限なし。容量は最大 2GB。サーバーの ffmpeg で H.264/AAC の MP4（最大 1080p）に変換し、サムネイルを作る。変換中は「処理中」と表示する |
| ファイル | 最大 2GB。形式は問わない |
| ボイスメッセージ | 最大 30分。Opus/AAC で録音する |
| 位置情報の送信 | 地図で選んだ地点を送る。地図には OpenStreetMap を使う |
| アルバム | トークごとに作る。1アルバムあたり最大 1,000件、写真と動画を入れられる |
| 保存期間 | **無期限**（サーバーの容量が続く限り）。管理者は期間を指定して自動削除するよう設定できる |
| 自動ダウンロード | 写真は自動。動画は Wi-Fi のときだけ自動（設定で変えられる） |

### 3.5 グループ向けの機能

| 機能 | 仕様 |
|---|---|
| 投票 | 選択肢は最大 10個。締切は最大 30日後。匿名投票と複数選択に対応 |
| ノート | 長文の投稿。写真・動画を最大 20件まで添付でき、コメントを付けられる |
| 予定 | 日時・場所・出欠確認、リマインド（1週間前〜1時間前）。候補日に ○△× で答える日程調整もできる |

### 3.6 通話

| 機能 | 仕様 |
|---|---|
| 種類 | 音声 / ビデオ。1対1とグループ（インスタンスの人数まで） |
| 発信 | トーク画面の通話ボタンから。グループでは全員を呼び出す |
| 呼び出し | **60秒** で打ち切り、発信側は「応答なし」、着信側は「不在着信」とトークに残す |
| 着信（Android） | 画面ロック中は全画面の着信画面、使っている最中はヘッドアップ通知。着信音を鳴らし続ける。Core-Telecom で OS の通話機能と統合する |
| 着信（iPhone） | §2.1 のとおり |
| 通話中の操作 | ミュート、スピーカー切替、カメラの ON/OFF、前後カメラの切替、最小化して他の画面を使う（Android はピクチャーインピクチャー） |
| 画面共有 | Android と PC から。iPhone は見る側だけ |
| 背景ぼかし | PC と Android で対応 |
| 通話中の別着信 | 「通話中」として相手に返し、自分側には不在着信を残す |
| トークへの記録 | 「通話 3:25」「不在着信」「キャンセル」 |
| 通話履歴 | 通話の一覧画面（発信・着信・不在） |
| 画質 | 1対1は最大 720p。回線に応じて自動で調整する |

### 3.7 通知

| 機能 | 仕様 |
|---|---|
| 送り方 | iPhone・PC は Web Push（iOS では Declarative Web Push を優先）。Android は FCM（使えない端末は UnifiedPush） |
| 送り先 | 新着があったとき、その画面を開いていない端末に送る |
| 表示 | タイトルは送信者名（グループならグループ名）、本文はメッセージ。内容を表示しない設定のときは「新着メッセージがあります」とだけ出す |
| まとめ表示 | 同じトークの通知はまとめる |
| 通知オフ | トークごとにオフにできる。メンションだけは届くようにできる |
| 一時停止 | 1時間 / 翌朝 8時まで |
| バッジ | アプリアイコンに未読の合計数を出す |
| 通知から返信 | Android で対応 |
| 再登録 | iPhone は、起動のたびに通知の購読を確認して登録し直す。期限が切れた購読（404/410 が返るもの）は削除する |
| 案内 | iPhone でホーム画面に追加していないことを検出したら、追加手順を図で案内する |

### 3.8 設定

文字サイズ（4段階、OS の設定に連動させることもできる）、ダークモード（OS 連動 / 固定）、テーマカラー、言語（日本語 / 英語）、キャッシュ削除、自動ダウンロード、アニメーション停止、URL プレビュー、入力中表示、既読送信。

### 3.9 バックアップ・データ

- サーバー側で一括してバックアップする。DB のダンプとメディアを、日付付きでまとめて保存する（既定 14世代）。端末側でのバックアップは不要。
- 機種変更は、新しい端末でログインすれば履歴をすべて表示できる（サーバーに全履歴があるため）。
- トーク履歴をテキストで書き出せる（.txt）。

### 3.10 v1 でやらないこと

- **エンドツーエンド暗号化**: サーバーは自分の管理下にあるので、通信は TLS、保存先はディスク暗号化（LUKS 推奨）で守る。全文検索やリンクプレビューをサーバー側で行うためでもある。将来の課題とする。
- 公開チャンネル、知らない人との連絡、友だち検索
- 有料コンテンツ、ニュース、ショッピング
- 翻訳

## 4. サーバー構成

```
[iPhone PWA / PC] ──HTTPS/WSS──┐
[Android APK]     ──HTTPS/WSS──┤
                               ▼
                           [caddy] ──> [api] ──> [postgres]
                               │         │ └──> media volume
                               │         └──> [worker] (ffmpeg, サムネイル, OGP)
                               └──> [livekit] (シグナリング)
   端末 ──UDP/TCP (メディア, TURN)──> [livekit]

[api] ──Web Push──> Apple / Mozilla / Google の配信サービス
[api] ──FCM──────> Google
[api] ──UnifiedPush──> [ntfy]（任意）
```

| コンテナ | 役割 |
|---|---|
| caddy | HTTPS（Let's Encrypt で証明書を自動取得）、静的ファイルの配信、APK の配布 |
| api | Node.js 22 + TypeScript + Fastify。REST と WebSocket、認証、通知の送信、LiveKit のトークン発行 |
| worker | ジョブ処理。動画の変換、サムネイル作成、EXIF の除去、OGP の取得、予約送信、通知の再送 |
| postgres | PostgreSQL 17 + PGroonga（日本語の全文検索用） |
| livekit | 通話用の SFU（TURN を内蔵）。単一ノードで動かす |
| ntfy | 任意。Google Play 開発者サービスのない Android 端末用 |

### 4.1 ネットワーク要件

| ポート | 用途 |
|---|---|
| 80, 443 / TCP | HTTPS、証明書の取得 |
| 7881 / TCP | LiveKit（UDP が通らないときの TCP 経路） |
| 3478 / UDP | TURN |
| 50000–50200 / UDP | 通話の音声・映像 |

- グローバル IPv4 アドレスとドメインが必要。
- 回線が CGNAT（グローバル IP を複数の契約者で共有する方式）でポートを開けられない場合は、固定 IP のオプションを契約するか、TURN だけを VPS に置く。
- 秘密鍵類（VAPID、セッション署名鍵、LiveKit の鍵）は、初めて起動したときに自動で作り、`data/secrets.json` に保存する。FCM のサービスアカウント JSON だけは、利用者が自分で置く。

## 6. 開発フェーズ

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| 1 | Docker Compose での起動、セットアップ、招待、ログイン、テキストのトーク、既読、PWA | iPhone と Android のブラウザで、メッセージを送り合える |
| 2 | 通知（Web Push）、バッジ、ホーム画面への追加案内 | アプリを閉じた iPhone に通知が届く |
| 3 | 写真・動画・ファイル・音声、アルバム、動画の変換 | iPhone で撮った動画を Android で再生できる |
| 4 | 通話（LiveKit）、iPhone の着信フロー、通話の記録 | モバイル回線と Wi-Fi の組み合わせで、1対1とグループの通話がつながる |
| 5 | Android APK（FCM、全画面着信、Core-Telecom） | 画面ロック中の Android で着信が鳴り、応答できる |
| 6 | 返信、リアクション、編集、取消、アナウンス、検索、スタンプ、投票、ノート、予定、予約送信 | §3 の機能がすべて動く |
| 7 | バックアップ、インストール手順、CI | 何も入っていない Ubuntu に、手順書どおりに構築できる |
