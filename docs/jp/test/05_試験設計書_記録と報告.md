## 本書の位置付け

- ISO/IEC/IEEE 29119-3:2021 の試験の状況の報告（7.3）、完了の報告（7.4）と、IEEE 829-2008 の実行の記録（13）、事象の報告（14）、試験の報告（16）を束ねる。

## 1. 実行の記録

|レベル|記録の形|置き場|保持|
|---|---|---|---|
|L0〜L5|CI の job のログと、赤の一覧の道具の出力（一覧に無い赤の数、now green の行）、平文検査の結果|公開リポジトリの運営者の実行の記録|運営者の保持の期間|

## 2. 事象の報告

- 事象（欠陥）は、再現する入力と期待と実際を持つ「失敗する試験」としてリポジトリに置く（第1章 DT-1-4）。試験が書けない事象は報告しない。設計の誤りなら仕様の改訂として扱い、試験はその改訂に合わせて直す。
- 利用者からの報告（公開リポジトリの Issues、security.txt）は、家族の情報を含まない形で再現する試験に書き直してから事象になる。脆弱性は Private vulnerability reporting の経路で受け、修正の版と同時に公開する（第13章 7）。
- 設計どおりの赤（NRSD の物が無い間）は事象ではなく、一覧の行（第1章 4.2）。

## 3. 状況の報告（29119-3 7.3）

- 進捗は状態で残す：ブロック × 手順の表（開発者の手元の進捗の記録。Git の外）と、レベルごとの「緑・赤・CI 未」、平文検査の結果。物語を持たない。

## 4. 完了の報告（29119-3 7.4。リリースごと）

|節|中身|出どころ|
|---|---|---|
|行った試験の要約|レベルごとの試験の数と結果（緑・一覧の赤の数）、平文検査|CI の最後の実行と L6 の記録|
|計画からの逸脱|回さなかった試験と理由（例：最低要件の実機が無く L6 の一部を省いた、回線の形 C を確かめていない）|手順書の記録|
|完了の評価|第1章 2 の出口の基準をレベルごとに満たしたか|同上|
|妨げた要因|NRSD の物の欠け（一覧の赤の行）、環境、実機|一覧|
|測度|性能（第3章 7）、見やすさ（第3章 8）、試行の率（第3章 9）、実測（第3章 10）|記録|
|残る危険|第16章 5 の既知の制約のうち試験で確かめられない物（番号だけ）と、実測で不可と出た項目の代替の採用|第16章、記録|
|成果物と再利用できる資産|試験のコード、データの生成の道具、fixtures、検証ベクトル、試験用の代替|リポジトリ|

- 置き場：`CHANGELOG.md` の版の節と対にして手順書の記録に 1 版 1 つ。公開リポジトリには試験のコードと CI の記録だけを置き、L6 の記録の要約（環境と結果。家族の情報なし）を Release のノートに 1 行で書く。
