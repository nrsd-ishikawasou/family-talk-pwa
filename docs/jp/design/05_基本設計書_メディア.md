## 本書の位置付け

- 概要設計書 第5章「写真、動画、ファイル、音声、地図」を詳細化し、未決事項 O-07「保存の期間と容量の既定」を閉じる。
- 前提：第12章 DD-12-7（添付は端末がファイルごとの鍵で暗号化し、サーバーは暗号文の大きさとハッシュだけを知る）。したがって設計計画書 D-8-2「家族のサーバーで変換する」は「送る端末で変換する」に改まり（第12章 18）、本章はその方式を定める。概要設計書 R-5-2-1 もこの読み替えで受ける（11）。
- 経路は第2章 5.6、添付のイベントは第4章 3.1（`ft.content.attachments/1`）。本章は添付の項目の形（`ft.content.attachment_item/1`）を定める。
- 準拠：一般的な通信アプリの標準の数値（調査資料 準拠の調査 2 §2）と送信の UI の慣行（準拠の調査 3 §9）、調査 I-08（形式の互換）、I-15（地図）、I-12（容量）、RFC 9110（Range、ETag、immutable）、WebCodecs（W3C）、MediaRecorder（W3C）、PMTiles v3、ODbL 1.0 と OSMF の帰属の指針、法務調査 L-5、L-6。

## 2. 目的と範囲

### 2.1 受ける要件

概要設計書 第5章の R-5-1-1〜R-5-6-2。対応は 11。

### 2.2 扱うもの・扱わないもの

- 扱う：送れる種類と上限、端末での処理（写真、動画、音声、ファイル）、添付の項目の形、アップロードと取得、取り込みとキャッシュ、再生できない形式、アルバム、容量と消す規則、地図、加工と文字の抽出。
- 扱わない：添付の暗号化の方式（第12章 5.7）、経路（第2章）、スタンプの作成（第4章 5.9）、通話（第6章）、画面の配置（第10章）、アンチウイルス、動画の編集。

## 3. 添付の項目（`ft.content.attachment_item/1`）

```
{ "id": "<媒体の識別子>", "kind": "photo|video|file|audio|sticker|avatar",
  "name": "<元のファイル名（255 バイト以内、NFC）>", "mime": "image/jpeg", "size": 1234567,
  "hash": "<暗号文の SHA-256>", "key": "<ファイルの鍵（base64url、32 バイト）>",
  "w": 1600, "h": 1200, "duration": 12.3,
  "thumb": { "id", "key", "hash", "w", "h", "size" }, "poster": { 同上 },
  "blurhash": "LKO2?U%2Tw=w]~RBVZRi};RPxuwH", "playable_hint": "standard|original",
  "waveform": [0..63 の 0〜255], "quality": "standard|high|original", "created_at": "<RFC 3339>" }
```

- `size` と `hash` は暗号文のもの（サーバーの記録と一致）。`w`、`h`、`duration` は端末が申告。
- `thumb` は写真・動画・スタンプ・アイコンに必ず、`poster` は動画に必ず、`blurhash` は写真・動画に必ず、`waveform` は音声に。
- 同じ媒体を転送で参照する時は同じ `id`、`key`、`hash` を使う（第4章 DD-4-15）。

## 4. 端末での処理

### 4.1 写真（DD-5-2）

|順|処理|備考|
|---|---|---|
|1|選択：OS の写真の選択（`<input type="file" accept="image/*" multiple>`。iPhone は互換モードで HEIC を JPEG に。Android のシェルは写真ピッカー。第9章）、カメラ（`capture`）、共有（Android のシェルの受け口。第9章）|50 件まで。超えたら案内|
|2|復号：`createImageBitmap(file, {imageOrientation: "from-image"})`。HEIC が来た場合（Android）は `ImageDecoder` で復号できれば続け、できなければ「この写真は送れません（形式）」|Safari 16.4 の `imageOrientation` は［要実測］。代替は EXIF の向きを読んで回転|
|3|画質の選択（送信の画面。既定は設定の値。標準）：長辺 1,600／2,560／無圧縮。オリジナルで 20 MB 超は高画質へ。画素数は 1 億まで|送信の画面に 3 択（準拠の調査 3 §9）|
|4|加工（任意。4.5）|—|
|5|再符号化：canvas → JPEG（品質 85）。EXIF は残らない（向きは 2 で適用済み）。オリジナルは再符号化せず、EXIF だけを除く（JPEG の APP1 を落とす。位置と撮影の情報の除去。向きは EXIF の向きを読んで画素を回転してから保存し直す）|設計計画書 D-8-3|
|6|サムネイル 320 と 1,280（長辺）、BlurHash（4×3）|—|
|7|暗号化（第12章 5.7）とアップロード（5）|—|

### 4.2 動画（DD-5-3）

|順|処理|備考|
|---|---|---|
|1|選択（写真の選択、カメラ、共有）。5 分・1 GB を超えれば「ファイルとして送る」を案内|—|
|2|判定：`mediabunny` で demux して、映像のコーデック（avc1）、プロファイル、解イメージ度、fps、音声（mp4a）を読む|iOS の写真の選択が変換した場合はこの時点で範囲に入っている［要実測］|
|3|範囲に入っていれば無変換（faststart でなければ moov を先頭に並べ替えるだけ）|—|
|4|範囲外（HEVC、4K、HDR、VP9 等）で `VideoEncoder` が使える端末：WebCodecs で復号 → 1080p 以下に縮小 → H.264 High で符号化（6 Mbps 目標、60fps 上限）→ 音声は元の AAC を通す（なければ無音）→ mediabunny で MP4（faststart）に多重化。HDR は SDR に落ちる（色の違いは注記）。進捗を表示。電池が 20% 未満なら確認|所要は再生時間と同程度［要実測］|
|5|変換できない端末（`VideoEncoder` なし、復号できない）：原本のまま送る。`playable_hint: "original"`。送信の画面に「相手の端末で再生できないことがあります」|—|
|6|ポスター（1,280）と BlurHash（`<video>` の 1 秒目を canvas へ）、長さ|—|
|7|暗号化とアップロード|—|

- 受け手：`canPlayType(mime; codecs=...)` と `MediaSource.isTypeSupported` で判定。再生できなければ「この端末では再生できません。保存して他のアプリで開く」（iPhone は HEVC を再生できる。Android は端末の HW による）。

### 4.3 音声（DD-5-4）

- 録音：長押しで録音、上へスワイプで固定、左へスワイプで取り消し、送る前に聞ける（準拠の調査 3 §7）。`MediaRecorder` の `mimeType` は `audio/mp4` → `audio/webm;codecs=opus` の順に `isTypeSupported` で選ぶ。30 分で自動停止。
- 波形：録音中の `AnalyserNode` から 64 点。
- 再生：1x/1.5x/2x、途中からの再開、スピーカー／受話口（Android はシェル。第9章）。
- 互換：iOS 16.4 で WebM/Opus、Android 138 と PC で MP4/AAC の再生を［要実測］。再生できない組み合わせがあれば、受け手の端末で WebCodecs の `AudioDecoder`（Chrome）または `<audio>` の代替で復号する手段を第2巡で足す。

### 4.4 ファイル（DD-5-5）

- 選択：OS のファイルの選択、共有。1 GB。
- 種類：端末が先頭の魔法数で判定（画像・動画・音声・PDF・zip・Office 等の一覧）。判定できなければ `application/octet-stream`。
- 受け手：PDF と画像と動画と音声は画面で開く。それ以外（SVG、HTML、実行可能ファイルを含む）は「保存」のみ。
- 名前の表示：元の名前。長い名前は途中を省略。

### 4.5 加工と文字の抽出（DD-5-11）

- 加工：切り抜き（比率の候補と自由）、回転（90 度と微調整）、反転、文字（色と大きさ）、手描き（色と太さ）、ぼかしとモザイク（範囲を塗る）、フィルター（数種）。canvas で端末の中。元に戻す（段階）。
- 文字の抽出：OCR の部品（Apache-2.0。WASM）と日本語の学習データ（約 15 MB）を初回に家族のサーバーから取得して端末に置く。写真を開いた画面の「文字を取り出す」→ 認識した文字を選択してコピー。外部に送らない。
- 加工した写真は新しい写真として送る（元は端末に残る）。

## 5. アップロードと取得

### 5.1 アップロード（DD-5-6）

1. 項目ごとに `POST /media/slots`（配列。kind と暗号文の大きさ。暗号化はストリームで行うので大きさは平文 + チャンクごとの 16 バイトのタグ + 先頭の版）。
2. 4 本の並列で `PATCH /media/{id}`（8 MiB ずつ。`Upload-Offset`）。サムネイル・ポスターを先に、本体を後に（受け手に早く見せる）。
3. 完了で `Upload-Complete: ?1` と `X-Content-SHA256`。不一致（`MEDIA-004`）は最初から。
4. 全部の項目が完了してから本文（`ft.content.attachments/1`）を送る（第4章 5.1）。
5. 失敗と再開：回線が切れたら `HEAD` で位置を取り直し続きから。スロットは 24 時間有効。24 時間を過ぎたら取り直し（最初から）。
6. 進捗：項目ごとと全体（バイト）。送信の画面に残り時間の目安。
7. 背景：iPhone と PC はページを閉じると止まる（Background Fetch は iOS 非対応）。送信中は「アプリを開いたままにしてください」の表示。画面のロックは可（Safari は背景でも短時間続く［要実測］）。Android はシェルが前面サービスで続ける（第9章）。

### 5.2 取得（DD-5-7）

- `GET /media/{id}`（Range）。端末は暗号文を OPFS に置き、復号して表示（画像は Blob URL、動画は MediaSource または復号済みファイルの Blob URL。大きい動画は Range で必要な分だけ取り、復号しながら再生する方式を全体実装設計書で定める）。
- 自動の取り込みの表（設定 > 写真と動画）：

|種類|Wi-Fi|モバイル|
|---|---|---|
|サムネイル・ポスター|常に|常に|
|写真の本体（1,280 またはオリジナル）|取り込む（既定）|取り込まない（既定）|
|動画|取り込む（既定）|取り込まない|
|ファイル|取り込む（既定）|取り込まない|
|音声|取り込む|取り込む（小さい）|

- 回線の判定：`navigator.connection`（Chrome）、なければ「Wi-Fi」とみなし設定で切り替え。Android のシェルは OS の判定を JS ブリッジで渡す。
- キャッシュ：OPFS。上限は端末の空きの 20%（設定で変更）。超えそうなら古い順に本体を消す（サムネイルは残す）。設定 > データと容量に、トークごとの使用量（大きい順）、種類ごとの削除、トークごと・期間ごとの削除。
- 端末への保存：iPhone は共有シート（「画像を保存」）、PC はダウンロード、Android はシェルが MediaStore へ（第9章）。保存する時に初回だけ「家族の外に出す時は写っている人の了解を」（第4章 DD-4-15）。

### 5.3 再生できない形式

- 判定は受け手の端末。「この端末では再生できません。保存して他のアプリで開く」。
- `playable_hint: "original"` の動画は、受け手の画面にその旨の印。

## 6. アルバム（DD-5-8）

- `ft.content.album/1`：`{album_id, title(50), description?(500), items: [attachment_item × ≤1,000], creator}`。トークのイベント。追加・削除は replace（最新が有効。端末は項目を `id` の和集合で解き、削除は `removed_ids` の欄で表す）。
- 一括のアップロード：300 件まで。写真と動画（動画は 5 分以内）。画質はアルバムの設定（既定は高画質。オリジナルも可）。
- トークあたり 100 個。一覧の「アルバム」から。アルバムの写真を端末に保存（一括）。
- 誰でも追加できる。削除はアルバムの作成者、項目の送信者、管理者。

|消す規則|なし（永久）|「N 年より古い動画の原本を消す」「N 年より古いオリジナルの写真の原本を消す」「ファイルも含める」。N は 1〜10|
|消す前の知らせ|30 日前から家族全員のトークに。対象の件数と大きさ|—|
|消した後|本文に「容量の整理で消えました」（端末が暗号文の 404 を見て表示）。サムネイルとポスターは残る|—|
|構成員ごとの使用量|管理者の画面に表示（暗号文の大きさから）|—|

- 消すのは暗号文（サーバーは中身を知らない）。端末のキャッシュに残っていれば端末では見られる。
- 構成員ごとの上限は設けない（家族の記録は共有のもの）。

## 8. 地図（DD-5-10）

### 8.1 データと配信

|項目|中身|
|---|---|
|データ|公開の地図の共同プロジェクトのデータ（ODbL 1.0）の公開のビルド（PMTiles v3、ベクトル）。設置の道具が取得し、管理者が選ぶ領域（既定：日本。都道府県の選択。世界も可）を `pmtiles extract` で切り出して /data/maps/base.pmtiles に置く。日本全域 z0–14 の大きさは［要実測］|
|スタイル|配布物に同梱（CC0 のデザイン。日本語のラベルを優先、なければローカル名）|
|フォント|Noto Sans の glyph の PBF（OFL-1.1。著作権表示と本文を同梱）。配布物に同梱|
|スプライト|配布物に同梱（MIT）|
|配信|caddy が /maps/ を静的に配る（forward auth で認証、Range、`ETag`、`Cache-Control: private, immutable, max-age=31536000`。更新はファイル名の版で）|
|帰属|地図の右下に「© OpenStreetMap contributors」とリンク。折り畳みは明示の操作のみ（OSMF の指針）|
|更新|管理者の画面（第11章）。年 1 回を勧める知らせ。全体の再取得（差分はない）。取得先は第12章 8 の一覧|

### 8.2 位置の送信と表示

- 送る：「位置情報」→ 現在地（`geolocation`。許可を求める）または地図で地点を選ぶ（長押し）→ ラベル（任意）→ `ft.content.location/1`。
- 表示：吹き出しに小さな地図（MapLibre で描く。タイルは家族のサーバー）。タップで全画面、「地図アプリで開く」（OS の地図の URL スキーム。外へ出るのは利用者の操作）。
- オフライン：端末が見た範囲のタイルは OPFS にキャッシュ（上限 200 MB。既定）。
- 現在地の共有（継続）は設けない（設計計画書 第7.2節「地点を 1 回送る」）。

## 10. 失敗の扱い

|失敗|扱い|
|---|---|
|HEIC を復号できない（Android 8.x）|「この写真は送れません（形式）」。OS の写真アプリで JPEG に書き出す案内|
|動画の変換が途中で失敗（メモリ、電池）|原本のまま送るかを確認（`playable_hint: original`）|
|アップロードの再開でスロットの期限切れ（24 時間）|最初から。キューに残る|
|暗号文のハッシュの不一致（取得時）|破棄して 1 回再取得。それでも不一致なら「壊れています」|
|受け手が再生できない|「保存して他のアプリで開く」|
|端末のキャッシュが満杯|古い順に本体を消す。サムネイルは残す|
|サーバーの容量が 100%|読み取り専用（`SRV-002`）。送信はキューに残り、管理者が対処すれば送られる|
|地図のデータがない（設置の道具が取得に失敗）|位置の吹き出しは「地図は準備中です」。管理者の画面に知らせ|
|地図の取得先が止まっている|更新できない。手元の地図で続く（第1章 12）|
|OCR の学習データの取得に失敗|「文字の抽出はあとで」。次回に再取得|
|`createImageBitmap` の向きが効かない端末|EXIF の向きを読んで自前で回転（代替の経路）|

## 12. 本章で宣言する既知の制約

|番号|既知の制約|理由|緩和|
|---|---|---|---|
|H-5-1|変換できない端末から送られた動画（HEVC 等）は、受け手の端末によっては再生できない|サーバーの変換がない（E2EE）|印と「保存して開く」の導線。iPhone の写真の選択の変換に期待（要実測）|
|H-5-2|HDR の動画は端末の変換で SDR に落ち、色が変わり得る（トーンマップの品質は OS 任せ）|WebCodecs にトーンマップがない|注記|
|H-5-3|端末の変換は時間と電池を使う|端末で行う|進捗、電池の確認、無変換の経路を優先|
|H-5-4|Android 8.x の一部の端末は HEIC を送れない|OS の復号の有無|案内|
|H-5-5|iPhone と PC はアップロード中にアプリを閉じると止まる|Background Fetch 非対応|表示とキュー。Android はシェル|
|H-5-6|サーバーは添付の種類を知らないため、種類ごとの上限と魔法数の検査は送る端末に依存する|E2EE|受け手の再判定と「開かず保存」|
|H-5-7|音声の形式が端末で分かれ（AAC／Opus）、再生の互換は実測に依る|MediaRecorder の実装の差|第2巡で復号の代替を足す|

［要実測］：iOS の写真の選択の動画の変換の条件；WebCodecs の VideoEncoder の Safari 16.4 での実動と所要時間；`createImageBitmap` の `imageOrientation`（Safari 16.4）；MediaRecorder の `audio/mp4` の対応（Chrome、WebView 138）と WebM/Opus の iOS 再生；WebView 138 の HEVC 再生；日本全域の PMTiles の大きさと切り出しの時間；Safari の背景でのアップロードの継続の時間。
