## 本書の位置付け

- 概要設計書 第8章「iPhone と PC のウェブアプリのシェル」を詳細化する。manifest、Service Worker、ホーム画面への追加、保存、権限、iPhone の制約の補い方、PC のブラウザの差、配信の完全性を定める。
- ウェブアプリの中身（画面、鍵、通知の表示、通話）は各章にあり、本章は「ブラウザの上でアプリとして動く仕組み」を持つ。Android のシェルは第9章。
- 準拠するものは次のとおり。
  - W3C：Web Application Manifest、Service Workers、Push API、Notifications、Badging、Screen Wake Lock
  - W3C：Storage（persist）、CSP Level 3、Fetch Metadata
  - OS とブラウザの提供者の文書（調査 I-01、I-13、第14章 4）、法務調査 L-15

## 2. 目的と範囲

### 2.1 受ける要件

概要設計書 第8章の R-8-1-1〜R-8-6-1。対応は 10。

### 2.2 扱うもの・扱わないもの

- 扱う：manifest、SW、追加の検出と案内、保存の構造、権限、制約の補い方、PC の差、CSP と Fetch Metadata、更新、複数の家族、オフライン。
- 扱わない：画面（第10章）、鍵（第12章）、通知の中身と規則（第7章）、通話の流れ（第6章）、Android（第9章）、WebKit 以外のエンジン、Share Target。

## 3. 仕組み

### 3.1 manifest（DD-8-1）

```text
{ "id": "/", "name": "<家族の名前>", "short_name": "<家族の名前（12 文字まで）>",
  "start_url": "/", "scope": "/", "display": "standalone", "lang": "ja", "dir": "ltr",
  "theme_color": "<家族の色>", "background_color": "#ffffff",
  "icons": [ {192, any}, {512, any}, {512, maskable}, {512, monochrome} ],
  "screenshots": [ ...（同梱。narrow と wide） ], "description": "家族の連絡" }
```

- api が返す（認証なし。家族の名前は平文。アイコンは同梱の絵柄を家族の色で着色したものを api が生成してキャッシュ）。
- 家族の色は、設置の時に家族の識別子から 8 色の表で決める。利用者には選ばせない。色の役目は、複数の家族に属する人のホーム画面でアイコンを見分けること。
  - 表：`#1F5FAD`、`#2E7D32`、`#B23A48`、`#6A3FA0`、`#8A5A00`、`#00796B`、`#C2185B`、`#455A64`
  - どれも白との対比が 4.5:1 以上（WCAG 2.2 の相対輝度）で、maskable のアイコンの白い絵柄が読める。
- Safari 26 以降は manifest がなくてもウェブアプリとして開くが、Web Push の条件のため必ず置く。

### 3.2 Service Worker

|責務|方針|
|---|---|
|プリキャッシュ|ビルド時の資産の一覧（ハッシュ付きの名前。JS、CSS、WASM、フォント、同梱の絵柄と音、index）。版ごとのキャッシュ名。古い版のキャッシュは activate で消す|
|ナビゲーション|`/`、`/r/*`、`/d/*`、`/i/*`、`/settings/*` は index を返す（SPA）。ネットワークが使えなければキャッシュ|
|API|`/api/*` はネットワークのみ（キャッシュしない）。失敗はアプリが扱う|
|添付・地図・manifest|SW は触らない（添付と地図はアプリが OPFS に、manifest はブラウザが取得）|
|push|第7章 5.1（取得・復号・`showNotification`・`setAppBadge`）。復号は IndexedDB の MLS の状態と Web Locks|
|notificationclick|`clients.matchAll` で開いているウィンドウがあれば focus して `/r/<room_id>` へ、なければ `openWindow`|
|pushsubscriptionchange|新しい購読を `PUT /me/devices/{id}/push`|
|更新|`skipWaiting` は画面の確認の後（DD-8-9）。`clients.claim` は activate で|
|メッセージ|画面との `postMessage`（版の通知、復号の依頼の結果の共有）|

- SW は認証の状態を持たない（Cookie はブラウザが付ける）。セッションが切れていれば push の取得が 401 になり、汎用の本文を出す。
- SW の寿命（iOS）は短い前提。復号は 10 秒以内に終える（第7章）。

### 3.3 ホーム画面への追加（DD-8-2、DD-8-3）

|状況|検出|振る舞い|
|---|---|---|
|iPhone の Safari のタブ|`display-mode: browser` かつ iOS の UA|参加の後（または起動時）に案内の画面：「共有ボタン、ホーム画面に追加、追加」の順の図（iOS 16〜17 と 18 以降の 2 種）、「追加したらホーム画面から開いてください」。通知の許可の求めは出さない|
|iPhone の standalone|`display-mode: standalone`|通常。最初のトークで通知の許可のボタン|
|Android のブラウザ（シェルでない）|Android の UA かつ JS ブリッジがない|「Android ではアプリをお使いください」+ APK の案内（第13章）。ブラウザのままでも使えるが通知は Web Push（着信は全画面にならない）|
|PC のブラウザ|それ以外|通常。`beforeinstallprompt` があれば設定に「アプリとしてインストール」|
|WebKit 以外のエンジン（iOS 26.2 以降）|判定できない|対象外（手順書）。不具合の報告の時に確かめる|

### 3.4 保存（DD-8-4）

|置き場|中身|暗号化|上限・消し方|
|---|---|---|---|
|IndexedDB `events`|room_id、pos、event_id、ts、kind、暗号文、復号済みの中身、関係|復号済みの中身は端末の保存の鍵|永久（端末から消す操作で）|
|`rooms`、`users`、`devices`、`receipts`|コピー|—|同期で更新|
|`queue`|transaction id、room_id、本文（暗号文）、状態、試行|端末の保存の鍵|送信で消す。7 日で失敗|
|`sticker_requests`|スタンプの削除の求め（自分が出した物と受けた物。求めた人、パックと絵柄、求めた日、最後に送った日。第4章 5.9）|端末の保存の鍵|応じられた時と取り下げで消す|
|`mls_state`|グループごとの状態|端末の保存の鍵|—|
|`keys`|端末の鍵（CryptoKey）、端末鍵、鍵バンドル|CryptoKey は抽出不可。鍵バンドルは端末鍵で|—|
|`settings`、`sync`|設定のコピー、最後の pos|—|—|
|OPFS `media/`|添付の暗号文|暗号文のまま|空きの 20%。古い順|
|OPFS `cache/`|復号済みの一時（表示用）|—|セッションごと|
|OPFS `search.sqlite`|検索の索引|なし（H-12-8）|再作成可|
|OPFS `maps/`|地図のタイル|—|200 MB|

- `navigator.storage.persist()` を初回に。結果は `settings` に残す。iOS 17 以降のホーム画面のアプリでは、そのドメインが「データの削除を免れるドメイン」に入るので真になる（WebKit のソース。調査資料 I-01 1.11。最低要件は 18 以上）。拒否されたら（PC、ホーム画面以外）、設定の画面で「保存は消えることがあります」と示す。
- ロックダウンモード（iOS 17 以降）では IndexedDB が無い。起動時に `indexedDB` が無ければ、本システムは動けないので「ロックダウンモードでは使えません」の画面と除外の案内を出す（4、第10章 7）。
- 再開：起動、`sync.pos` の読み出し、`/sync?since`、`queue` の再送の順。SW と画面の両方が IndexedDB を開くため、書き込みは Web Locks で直列化。
- 容量の逼迫（`estimate()` で 90%）：添付の本体を古い順に消す。

### 3.5 権限（DD-8-5）

|権限|求める時|拒否の時|
|---|---|---|
|通知|standalone で最初のトークを開いた時のボタン|使えるが通知なし。設定に再許可の案内（OS の設定）|
|カメラ・マイク|通話の開始・応答のたび|音声のみ／受けるだけで参加。設定への案内|
|位置|位置の送信の時|地図で地点を選ぶ|
|画面の共有|PC の共有の開始の時|—|

## 4. iPhone の制約の補い方（DD-8-6）

|制約|補い方|章|
|---|---|---|
|鳴り続ける着信ができない|20 秒 × 3 回の通知（18.2 以降は 3 件が並び、毎回鳴る）、開いたら呼び出し画面（通知のタップ `/call/<call_id>`、起動と前面化の時の `/sync` の着信の確かめ）、不在のかけ直しは 1 操作|第7章 7、第6章 4.1|
|通知が tag で置き換わらず、表示から 30 秒は閉じられない（18.2 以降、26.4 以降）|着信の通知は `call_end` で閉じる（30 秒を待つ）。同じトークの新着は前の通知を閉じてから出す|第7章 5.2、7、H-7-8|
|ロックダウンモードでは IndexedDB と WebCodecs が無い|起動時に `indexedDB` の有無で判定し、「ロックダウンモードでは使えません」の画面と、Safari のサイトごとの設定で除外する案内を出す（第10章 7）。除外がホーム画面のアプリに効くかは資料で決まらない（9 の H-8-6）。動画の変換は無く原本を送る（第5章 H-5-8）|3.4、第5章 4.2、第10章 7|
|ロック中の通話が切れ得る|切れる前提。Wake Lock（18.4 以上）、復帰で再接続、画面の案内|第6章 5.2|
|通知の音を指定できない|着信とメッセージは通知の本文で区別。前面なら Web Audio の着信音|第6章 4.3|
|通知にボタンを置けない|タップでトークへ。返信は開いてから|第7章 5.4|
|通知を表示しない受信ができない|必ず表示（汎用の本文）|第7章 5.1|
|HEIC|写真の選択は OS が JPEG に変換して渡す（`accept` に型を個別に並べ、`image/*` を書かない）。「ファイルを選択」の HEIC は端末が復号|第5章 4.1|
|背景の処理ができない|開いた時に全差分。予約送信はサーバー|第2章 5.9、第4章 5.8|
|Share Target がない|アプリ内の「写真を選ぶ」|第5章|
|導入の手順|図の案内（3.3）|—|
|PiP|対応は要実測。アプリ内の小窓|第6章 5.1|
|画面の共有ができない|見る側だけ|第6章|
|保存領域が消え得る|persist、サーバーが正本、鍵バンドルのコピー|3.4、第12章|

- 構成員向け：設定 > ヘルプ > 「iPhone でできないこと」。管理者向け：手順書。

## 5. 更新とオフライン（DD-8-9）

- 起動のたびに `registration.update()`、`/version`。新しい版の SW が待機したら「新しい版があります。再読み込みしますか」。通話中・送信中は出さず、終わってから。
- 古い版で `NET-006`（最低限の版を下回る）なら更新の画面で止まる。
- オフライン：SW のキャッシュで画面が開き、IndexedDB のコピーを表示、送信はキュー、画面に「オフライン」のバナー。復帰で同期。

## 6. 配信の完全性（DD-8-8）

|手段|値|
|---|---|
|TLS|第12章 4|
|CSP|`default-src 'self'; script-src 'self' 'nonce-<応答ごとの乱数>' 'strict-dynamic' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; connect-src 'self' wss://<サーバー>; img-src 'self' blob: data:; media-src 'self' blob:; worker-src 'self' blob:; font-src 'self'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'self'; upgrade-insecure-requests`。`style-src` の `'unsafe-inline'` は地図の部品の要件（第2巡で nonce 化を検討）。nonce は index の応答ごとに api が暗号論的な乱数で 128 ビットを作る（CSP Level 2 の 4.2：方針を送るたびに独立に新しい値）。nonce を含む CSP は api が index の応答に付け、それ以外の応答（静的な資産、Service Worker）には caddy が nonce の無い値を付ける|
|COOP|`same-origin`。COEP は不要（OPFS の同期アクセスは sahpool）|
|資産|ハッシュ付きの名前で同じオリジンから。外部の CDN を使わない|
|Fetch Metadata|第2章 4.2|
|Referrer-Policy|`strict-origin-when-cross-origin`（プレビューの代理が外へ出す時は `no-referrer`）|
|Permissions-Policy|`camera=(self), microphone=(self), geolocation=(self), display-capture=(self)`|
|既知の制約|改竄された JavaScript は検知できない（第12章 H-12-2）|

## 8. 失敗の扱い

|失敗|扱い|
|---|---|
|SW の登録に失敗|画面は動く（通知なし）。設定に表示。再試行|
|プリキャッシュの取得に失敗（途中で切れた）|古い版のまま。次の起動で再試行|
|`persist()` が拒否|案内。動作は同じ|
|保存が消えた（iOS の削除）|起動時に `sync.pos` も鍵もなければ、新しい端末として承認する（第3章 4.4）。履歴は鍵のバックアップから|
|push の取得が 401（セッション切れ）|汎用の本文。開いた時にログイン|
|standalone でないのに通知の許可を求められた（Safari 26 の挙動の変化）|`display-mode` で判定するため起きない。起きれば許可の求めを出さない|
|CSP の違反|報告しない（外へ出さない。`report-to` を置かない）。記録は端末のコンソールのみ|

## 9. 本章で宣言する既知の制約

|番号|既知の制約|理由|緩和|
