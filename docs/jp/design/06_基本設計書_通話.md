## 本書の位置付け

- 概要設計書 第6章「通話」を詳細化する。基盤（SFU）、開始と着信、通話中、記録、暗号化を定め、設計計画書 D-5-2・D-9-2 の【要設計】（iPhone の制約の補い方）を設計する。
- 経路とイベントは第2章 5.7、6.2。通話の鍵は第12章 5.11。着信の通知は第7章 7。シェルの着信と音声の経路は第9章。到達性の分岐は第11章。
- 準拠するものは次のとおり。
  - 標準：W3C WebRTC 1.0、RFC 8829/8827/8834/8838/8843、RFC 7742/7874（コーデック）
  - 標準：RFC 5763/5764（DTLS-SRTP）、RFC 8656（TURN）
  - 調査：I-05、I-07、I-12、I-13、OS の提供者の通話の文書（調査 I-04、J3）
  - 慣行：一般的な通信アプリの通話の慣行（調査資料 準拠の調査 2 の 5、準拠の調査 3 の 8）
  - 法務調査 L-10、L-12

## 3. 基盤（DD-6-1、DD-6-2）

### 3.1 SFU の設定（deploy/livekit.yaml。初期値）

### 3.2 人数と帯域

|構成|映像の上限|音声のみ|上りの目安（720p を 1 人が送り、他が 360p を受ける）|
|---|---|---|---|
|既定|8 人|家族の人数（≤20）|8 人：上り約 10 Mbps、下り約 15 Mbps（推奨の機械と 30 Mbps 以上の上り）|
|管理者の設定|2〜20|—|第11章の目安の表|

- 上限に達した参加は `CALL-006`（新設。「人数の上限です」）。音声のみなら入れる（映像を切って参加）。
- 画質の既定は 720p（送り）。1080p は「高画質」の設定で、Wi-Fi かつ 2 人の時だけ（SFU の設定で上限）。

## 4. 開始と着信（DD-6-3、DD-6-4）

### 4.1 1 対 1

|順|発信者|サーバー|相手|
|---|---|---|---|
|1|トークの「通話」（音声／ビデオ）を押し、`POST /rooms/{id}/calls`|通話を作り、SFU のトークンを返す。相手の全端末へ `call.ring`（WebSocket）と通知（`kind: call`、high、TTL 60）|Android はシェルが CallStyle、iPhone は通知 × 4 と呼び出し画面、PC は呼び出し画面 + 通知|
|2|呼び出し画面（相手の名前と写真、「呼び出し中」、取消）。SFU に接続して待つ|60 秒の計時|応答（`POST /calls/{id}/join`）、拒否（`/decline`）、無視|
|3|—|応答：他の端末に `call.state: active`（止める）。拒否：`call.declined` を発信者へ、記録。60 秒：`call.missed` を双方へ、記録、相手に「不在着信」の通知（`kind: call_end`）。取消：`call.cancelled`|応答した端末が SFU に接続、鍵は MLS で届く（第12章 5.11。発信者が開始時に配っている）|
|4|通話中（5）|—|通話中|

- 相手が通話中（別の通話に参加中）：`CALL-003`。発信者に「{name}さんは通話中です」を示す。相手には不在の記録と「通話中に {name}さんから着信」の知らせを残し、通話の後に見える（`ft.event.call/1` の `missed`、`reason: busy`。第2章 12）。
- 相手が「着信を受けない」：`CALL-005`。発信者に「{name}さんは着信を受け付けていません。メッセージを送れます」。記録は残さない（相手の選択）。
- 発信者が自分の通話中に別の人へ発信：できない（通話を終えてから）。
- 同じトークで互いに同時に発信：`CALL-002` で先の通話に合流（第2章 11）。

### 4.2 グループ

|順|開始する人|サーバー|構成員|
|---|---|---|---|
|1|「通話」（音声／ビデオ）を押し、`POST /rooms/{id}/calls`|通話を作る。`call.started` を全端末へ、通常の通知「{name}さんが通話を始めました」（ミュートの規則に従う）|トークの上部にバナー「通話中（3 人）。参加」。着信の画面は出ない|
|2|通話中|参加・離脱を `call.state` で|いつでも参加（`/join`）。鍵は参加のたびに MLS で届く（10 秒の猶予の規則）|
|3|—|最後の 1 人が離れて 60 秒で終了。`ft.event.call/1`（ended、時間、参加者）|—|

- グループ通話の「不在」はない（バナーと通知だけ）。記録には「通話がありました（n 人、m 分）」。
- 音声のみのグループ通話は映像のボタンで途中からビデオにできる（上限の範囲）。

### 4.3 着信音

|端末|着信音|選択|
|---|---|---|
|Android|通知チャネル「着信」の音（OS の選択。既定は OS の着信音）|OS の設定（シェルが開く）|
|iPhone|通知の音は OS の既定（選べない）。前面の呼び出し画面では Web Audio で同梱の音（3 種。NRSD の自作、CC0）|設定「通話」で 3 種から|
|PC|同梱の 3 種|同上|

- 相手ごとの着信音は設けない（慣行）。
- 「着信を受けない」：設定「通話」。有効の間は着信が来ず、メッセージは届く。一覧の自分の名前に印はない（相手には発信時に知らせる）。

## 5. 通話中（DD-6-5、DD-6-6、DD-6-7）

### 5.1 操作

|操作|iPhone|Android|PC|
|---|---|---|---|
|マイクの ON/OFF|可|可|可|
|スピーカー／受話口／外部|OS に委ねる（ビデオはスピーカー、音声は受話口。外部機器は OS の UI）。ボタンは出さない|シェルの OS の通話の経路（受話口、スピーカー、有線、無線）|出力の選択（`setSinkId`）|
|カメラの ON/OFF、前後|可|可|可（複数のカメラの選択）|
|最小化|アプリ内の小窓（他の画面を見ながら）。アプリを離れると切れ得る|PiP（シェル。第9章）|小窓|
|画質|3 択|3 択|3 択|
|データの節約|3 択（モバイルの判定は OS の情報。iPhone は判定できないので「常に」「しない」の 2 択）|3 択|2 択|
|音声のみに落とす|可|可|可|
|画面共有|不可（見る側のみ）|不可（第1版。見る側のみ）|可（画面／ウィンドウ／タブ。音声は対応ブラウザ）|
|背景のぼかし|可（負荷で自動で無効）|可（同左）|可|
|文字のチャット|トークをそのまま（小窓にして）|同左|同左|
|参加者の表示|音声：リスト。ビデオ：2×2 のグリッド（5 人以上はページ）／フォーカス（話者の自動または固定）|同左|最大 3×3|

- 画質の 3 択の意味：高画質 = 送信 1080p（2 人・Wi-Fi の時）、受信は層の最大；Wi-Fi のときのみ高画質 = Wi-Fi なら上、モバイルなら標準；標準 = 送信 720p。
- データの節約：しない = 上記；モバイルのみ = モバイル回線で「常に」の挙動；常に = 送信 360p、受信 180p、カメラは既定で OFF。既定は「しない」（画質を下げるのは本人が選んだ時だけ）。
- 背景のぼかし：端末内の人物の分割モデル（Apache-2.0。WASM と WebGL）で canvas に合成する。送るのは `MediaStreamTrackProcessor`（対応ブラウザ）か `canvas.captureStream` で行う。15 fps を下回る端末では自動で無効にし、設定に「この端末では使えません」。

### 5.2 iPhone の制約（DD-6-6）

|状況|振る舞い|
|---|---|
|通話中の自動消灯|Wake Lock（`navigator.wakeLock.request("screen")`。iOS 18.4 以上）。16.4〜18.3 は無音の小さな映像をループ再生して消灯を止める（効くかは［要実測］。効かなければ「自動ロックを切ってください」の案内）|
|画面のロック|通話は切れる（またはミュート）前提。復帰で再接続（5.3）。画面に「画面をロックすると通話が切れます」|
|アプリを背景に|同上。相手に「{name}さんが離れました（再接続を待っています）」|
|許可（マイク、カメラ）|通話の開始のたびに `getUserMedia`。拒否されていれば設定への案内（OS の設定 > ウェブサイト）|
|CallKit なし|着信は通知（第7章）。OS の電話の着信画面にならない（H-6-1）|

### 5.3 再接続（DD-6-7）

- SFU の SDK の自動再接続（30 秒。ICE の再開、回線の切り替えに追従）。30 秒を超えたら「接続が切れました」+「再参加」。再参加は同じ通話に入る。鍵は keyring に残り、新しい鍵が配られていれば MLS で届く。
- 相手の画面：10 秒で「接続が不安定」、30 秒で「離れました」。
- 品質の表示：接続の種類（直接、または TURN の中継）、往復の時間、パケットの損失を小さく示す。

## 6. 記録（DD-6-8）

|イベント|誰が|トークの表示|一覧|
|---|---|---|---|
|started（グループ）|サーバー|「{name}さんが通話を始めました」|—|
|ended|サーバー|「通話 12:34（n 人）」|発信・着信|
|missed（1 対 1）|サーバー|「不在着信」（受け手）、「応答なし」（発信者）|不在（赤）。連続の回数|
|declined|サーバー|「拒否されました」（発信者）、「拒否しました」（受け手）|—|
|cancelled|サーバー|「キャンセル」|—|

- 一覧（`/me/calls`）：全トークの通話を新しい順。絞り込み（発信・着信・不在）。タップで発信。
- 通話の記録は平文のイベント（`ft.event.call/1`）。参加者と時間はメタデータ（第12章 H-12-3）。

## 7. 暗号化の運用（DD-6-9）

- 第12章 5.11 の規則。本章の補足：
  - 鍵の配布は通話の MLS グループ（= トークのグループ）の本文（`ft.content.call_key/1`）。1 対 1 の発信者は `POST /rooms/{id}/calls` の直後に鍵 0 を配る。グループの参加者の増減で配り直す人は「参加者のうち端末の識別子が最小の端末」。
  - SDK の `ExternalE2EEKeyProvider` 相当の設定を全端末で統一する。keySize 128、keyringSize 256、ratchet 0、sharedKey false、failureTolerance -1。
  - 鍵が届く前のフレームは 10 フレームまで待ち、無音と黒。届けば回復。
  - iOS 17.2 未満はサイマルキャスト不可（SDK の制約）なので、1 層（360p）で送る。受け手の層の選択は効かない。
  - SFU の Webhook とシグナリングは E2EE の外（メタデータ）。
- DTLS-SRTP は SDK の既定。TURN は暗号文を中継するだけ。

## 9. 失敗の扱い

|失敗|扱い|
|---|---|
|SFU が止まっている（`CALL-004`）|「通話を始められません」。管理者に知らせ（第11章の health）|
|UDP が通らない|SFU の TCP（7881）、TURN（UDP 3478）、TURN の TLS（5349）の順に SDK が試す。全部だめなら「接続できません。回線の設定をご確認ください（管理者）」。第11章の分岐|
|相手の全端末が通知を受けない（購読なし、オフライン）|60 秒で不在。記録と不在の通知（次に開いた時）|
|応答した直後に切れた|再接続（30 秒）。超えたら ended（短い）と再発信の導線|
|鍵が届かない（MLS の遅れ）|10 フレームの待ちの後、無音と黒。「相手の鍵を待っています」。30 秒で再参加の案内|
|人数の上限（`CALL-006`）|音声のみで参加するかを問う|
|カメラ・マイクの許可がない|OS の設定への案内。音声のみ／受けるだけで参加できる|
|ぼかしが重い|自動で無効|
|iPhone が画面をロック|切れる（または復帰で再接続）。相手に表示|
|通話中にサーバーが更新で再起動|SFU の再起動で全員が切れる。更新の前に「通話中は更新しない」（第13章）|

## 10. 本章で宣言する既知の制約

|番号|既知の制約|理由|緩和|
|---|---|---|---|
|H-6-1|iPhone では OS の電話の着信画面にならず、ロック中は 4 回の通知の後に不在になる|CallKit と PushKit はネイティブ専用（I-01）|通知の繰り返し、呼び出し画面|
|H-6-2|iPhone は画面のロックとアプリの背景化で通話が切れ得る|OS の仕様|再接続、案内|
|H-6-3|Android の画面共有は第1版で提供しない|WebView の getDisplayMedia 非対応。シェルの画面の取得を WebView の経路に載せる設計は第2版|PC からの共有を見られる|
|H-6-4|iPhone はスピーカー／受話口の切り替えのボタンを持たない|OS の仕様（Web から選べない）|OS の自動と OS の UI|
|H-6-5|DS-Lite と事業者の NAT の家庭では VPS（または固定 IP）なしに通話が成立しない|調査 I-05|第11章の分岐と手順書|
|H-6-6|通話のメタデータ（誰といつ、参加者、時間）は平文|配送に要る|第12章 H-12-3|
|H-6-7|iOS 17.2 未満ではサイマルキャストが使えず、受け手の回線に応じた画質の調整が効かない|SDK の制約|1 層の 360p|
|H-6-8|グループ通話の品質は家族のサーバーの上りの帯域に律速され、人数の上限を超えると参加できない|自宅の回線|管理者の設定、音声のみの参加|

［要実測］の事項は次のとおり。

- iOS のホーム画面での E2EE 通話（Worker + 変換 API）、画面のロックと背景化、Wake Lock の代用
- AirPods 等の切り替え、Android のシェルの音声の経路と Chromium の自動モードの相互作用
- ぼかしの負荷、MAP-E での TURN、8 人の通話の帯域
- 1 層の E2EE の画質、WebView 138 の createEncodedStreams の経路
- caddy と api から `host.docker.internal:7880` への到達（host のファイアウォールの INPUT の規則）
