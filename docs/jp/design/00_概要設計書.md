## 本書の位置付け

### 本書の役割

- 設計計画書を受け、システム全体の構成と方式の大枠を定義する。範囲の定義は本書で行う。
- 本システムは2つのシステムからなり、両者の間に多様な通信が発生する。サーバー側は家族のサーバーで、管理者向けの画面を持つ。クライアント側は iPhone のホーム画面のウェブアプリ、Android のネイティブのシェル、PC のブラウザで、構成員向けの画面を持つ。本書はこの2つを1つの仕様の上に置く。機能の章（第3〜7章）は両側の責務を1つの章に書き、両者の境界は第2章「サーバーとクライアントの境界」に1か所で定義する。クライアント側に固有の OS に依存する部分は第8章と第9章（シェル）、サーバー側に固有の運用は第11章に書く。
- 各章の詳細は基本設計書に譲る。本書で全体を閉じてから詳細に入る。
- 試験は、本書および基本設計書と対になる別の文書群で扱う。
- 法務は別の文書（法務調査）で調べ、本書からはリンクする。

### 本システムが守るもの・守らないもの（全章の前提）

- 守るもの：家族の連絡の内容（メッセージ、写真、動画、ファイル、音声、通話、誰がいつ誰と連絡したかの記録）と、家族がいつでも連絡を取り合えること［D-2-1］。
- 守らないもの：家族の外との連絡（不特定多数、他の家族のサーバー、他の通信アプリ、電話網、緊急通報）、連絡以外の機能（決済、買い物、ニュース、翻訳）、認証なしの公開の共有［D-2-7］。
- 本システムは特定の製品の名称、外観、配色および画面の構成を模倣せず、準拠した元の名称を資料に記さない［D-2-5］。同種のソフトウェアの慣行は調査資料の「準拠の調査」に一般名詞で記してある。

### 用語

### 前提

- 構成員は技術を見ずに使える［D-3-4］。高齢者と子どもがいる［D-3-5］。管理者は Ubuntu と Docker を扱える［D-3-6］。
- NRSD は家族のサーバーを運営せず、データを受け取らず、接続する手段を持たない［D-3-7］。
- iPhone はホーム画面のウェブアプリであり、鳴り続ける着信と画面のロック中の通話の継続は実現できない。これは本システムの既知の制約として第16章で宣言する［D-5-2］。
- 既知の制約ゼロは不可能であり、既知の制約は第16章で宣言する。

### 範囲

- 扱う：家族のサーバー、アプリ（3種のシェルと共通の画面）、公開リポジトリ、外部の組織（プッシュ配信サービス、名前の解決、証明書の発行）との接点、管理者の運用、NRSD の関与点。
- 扱わない：家族の外との連絡、連絡以外の機能、認証なしの公開、業務での利用（「守るもの・守らないもの」）。1人が複数の家族に属する場合の扱いは第3章（O-04）。

### できなければならないこと

- 1-1 境界と構成要素
  - R-1-1-1 サーバー側、クライアント側（シェルごと）、公開リポジトリ、外部の組織のそれぞれについて、持つもの・持たないものが一意に決まっている。
  - R-1-1-2 家族の外との連絡、連絡以外の機能、認証なしの公開、NRSD の設備への接続が境界の外にあることが明示されている。
  - R-1-1-3 1つの家族に1つのサーバーという単位が、データとアカウントの単位と一致している。
- 1-2 データ
  - R-1-2-1 全データについて、生成元・保存先・公開/非公開・書き込み担当が決まっている。対象は、構成員、端末、セッション、招待、トーク、イベント、関係、既読、添付の原本と変換物、通話の記録、通知の購読、設定、バックアップ、ログ、地図。
  - R-1-2-2 識別子の体系（時系列に並ぶ一意の識別子）と、データの形式の版（API、DB のスキーマ、イベントの形式、アプリ）が決まっている。
  - R-1-2-3 秘密情報の置き場と持ち主が一覧になっている。対象は、セッションの署名鍵、通知の鍵、通話の中継の鍵、DB のパスワード、DNS の API トークン、Android の署名鍵、端から端の暗号化の鍵。
  - R-1-2-4 保持と削除の方針（送信の取消、退出した構成員、容量の上限、バックアップに残るもの）が決まっている。
  - R-1-2-5 日本語のファイル名、絵文字、長い本文を扱える。
- 1-3 データの流れ
  - R-1-3-1 招待と参加、送信と配信、メディアのアップロードと変換と配信、通話の開始から終了、通知の送信から表示、バックアップと復元、更新の各流れが、始点から終点まで途切れない。
  - R-1-3-2 部分的な失敗（送ったがサーバーに届かない、変換の失敗、通知の落ち、再接続）でデータの食い違いが残らない。
  - R-1-3-3 回線が切れている間に書いたものは端末に保持され、つながった時に送られ、二重に届かない。
- 1-4 信頼と脅威
  - R-1-4-1 信頼の境界（端末と家族のサーバー、サーバーとプッシュ配信サービス、サーバーと外部の URL、管理者とサーバーの記録、NRSD と家族）が図で示されている。
  - R-1-4-2 脅威の一覧があり、対策または既知の制約が第16章に結ばれている。脅威は、招待のリンクの漏れ、端末の紛失、サーバーへの攻撃、管理者の閲覧、構成員同士、改竄された JavaScript、プッシュ配信サービスが見るメタデータ、鍵の喪失。
- 1-5 外部への依存
  - R-1-5-1 プッシュ配信サービス、名前の解決、証明書の発行、公開リポジトリ、地図のデータの供給元が止まった時の振る舞いが決まっている。
- 1-6 端末と人
  - R-1-6-1 1人が複数の端末を同時に使え、新しい端末でそれまでの連絡を見られる。
  - R-1-6-2 端末の紛失と機種変更に備え、本人と管理者が端末のログインを取り消せる。
  - R-1-6-3 管理者の引き継ぎ、複数の管理者、管理者の不在（サーバーの停止）の扱いが決まっている。
- 1-7 共通の方針
  - R-1-7-1 規模と性能の目安（人数 2〜20、トークとメッセージの数、添付の容量、通話の人数、回線の上り）が全章で共通している。
  - R-1-7-2 次の方針が全章で共通している。失敗の扱い（エラーコード表、利用者への見せ方、記録）。記録（ログ）の方針。時刻の扱い（サーバーの時刻が正、端末のずれ、タイムゾーンの表示）。版の互換の宣言（期間）。言語（日本語のみ、後から加えられる形）。
- 1-8 運営
  - R-1-8-1 NRSD の関与点（公開、配布物の署名、Android の口座、問い合わせの受け口）と関与しない点（家族のサーバー、家族のデータ）が決まっている。
  - R-1-8-2 管理者の運用（設置、招待、更新、バックアップ、知らせへの対処）と、費用（機械、回線、ドメイン、Android の口座）とその負担者が決まっている。
- 1-9 図と対応
  - R-1-9-1 2つのシステムの構成図、データの流れ図、信頼の境界図がある。
  - R-1-9-2 設計計画書の決定番号から本書の要件番号への対応表がある。
  - R-1-9-3 章の依存表と、基本設計に入る順序がある（本書末尾）。

## 2. サーバーとクライアントの境界

受ける決定は次のとおり。

- D-7-7「全員の画面で同じ順、回線が切れている間は保持、二重に届かない」
- D-9-5「通話は SFU 経由」
- D-10-1「iPhone と PC は Web Push」
- D-10-2「Android は Web Push の送信路と UnifiedPush」
- D-14-5「記録を失わずに更新」
- D-15-3「アプリは家族のサーバーから配る」
- D-3-7「NRSD の設備への自動の送信を持たない」
- 準拠標準 1・3・4・5・6（公開のメッセージングのプロトコルの語彙、Web Push、WebRTC、認証、データの形式）
- L-14

定義すること：サーバー側とクライアント側の間のすべてのやり取りの種類、形、認証と認可、冪等性、版。機能の章はここを参照し、再掲しない。

### 範囲

- 扱う：HTTPS の API、WebSocket のイベント、通知の中身、通話のシグナリングと SFU のトークン、メディアの URL。配布物と版の情報の取得、管理者の画面の API、版の互換、境界の一覧（機械が読む定義）。
- 扱わない：各機能の意味（第3〜7章）、シェルの中の OS との JS ブリッジ（第8章、第9章）、家族のサーバーの外部との接続（第1章 1-5、第12章）。

### できなければならないこと

- 2-1 通信の種類
  - R-2-1-1 境界のやり取りが次の種類に分類され、それぞれの認証、認可、冪等性、版が決まっている。種類は、API（要求と応答）、WebSocket（サーバーからのイベント）、Web Push と UnifiedPush（通知）、通話のシグナリングとメディア。加えて、メディアの取得（Range）、配布物と版の情報、管理者の画面の API。
  - R-2-1-2 すべてのやり取りが TLS の上で行われ、WebSocket は Origin を検証し、API は cross-site の要求を拒む（Fetch Metadata）。
- 2-2 API の形
  - R-2-2-1 語彙が公開のメッセージングのプロトコルの仕様に準拠している（イベントと状態、関係の種類、既読の3種、入力中、削除、メディアの識別子、push の登録）。
  - R-2-2-2 API が OpenAPI 3.1 と JSON Schema 2020-12 で定義されている。識別子は UUIDv7、時刻は RFC 3339 の UTC、エラーはエラーコード表の番号で返る。
  - R-2-2-3 送信は端末が付ける transaction id で冪等であり、サーバーは順序と時刻を付けて全端末に同じ順で配る。
  - R-2-2-4 同期は since（最後に受け取った位置）による差分で行え、初回と再接続で全差分を取れる。
  - R-2-2-5 競合（同時の編集、既読の後退、構成員の変化中の送信）の扱いが決まっている。
- 2-3 WebSocket のイベント
  - R-2-3-1 イベントの一覧（メッセージ、関係、既読、入力中、構成員と端末の変化、着信と通話の状態、設定の変化、システムの知らせ）が AsyncAPI 3.1 で定義されている。
  - R-2-3-2 接続の認証、ping、切断と再接続と差分の取り直しが決まっている。
- 2-4 通知の中身
  - R-2-4-1 通知の中身は本文を含まず（トーク、イベント、未読の数、汎用の本文）、宣言型の Web Push の JSON と UnifiedPush の RFC 8291 の暗号化で送られる。
  - R-2-4-2 購読の登録、更新（pushsubscriptionchange）、失効（404、410）の扱いが決まっている。
- 2-5 通話
  - R-2-5-1 着信の合図（WebSocket と通知）、応答、拒否、終了、不在の判定と、SFU のトークン（短い期限、ルームの権限のみ）の発行が決まっている。
  - R-2-5-2 TURN の一時の資格情報（共有の秘密と期限）の発行が決まっている。
- 2-6 メディア
  - R-2-6-1 アップロードがスロットの先行発行（識別子を先に、中身を後に）と再開に対応している。取得が、認証付きの URL、Range、キャッシュ（不変の識別子に immutable）に対応している。
  - R-2-6-2 変換中の状態とサムネイルの取得の形が決まっている。
- 2-7 配布と版
  - R-2-7-1 家族のサーバーから、ウェブアプリ、Android のアプリ（APK）、版の情報（版の番号、取得先、ハッシュ、鍵の指紋）、手順書を取得できる。
  - R-2-7-2 API の版の付け方と、アプリまたはサーバーの版が古い時の振る舞い（最低限の版、期間での互換の宣言）を決めてある。
- 2-8 境界の一覧
  - R-2-8-1 境界のすべて（命令、型、イベント、エラー）が実装の前に1つの文書に定義され、サーバー側とクライアント側の型がそこから生成される。境界の変更はこの文書の改訂を経る。
  - R-2-8-2 NRSD の設備へのやり取りが境界に存在しない（公開リポジトリへの版の確認と取得を除く）。

### 基本設計で詰めること

- 各 API の経路と型、イベントの型、エラーコード表、版の番号、生成の道具。

### 依存と法務

### 範囲

- 扱う：初回の管理者、招待、アカウントとプロフィール、パスキーによるログインと回復、新しい端末の追加、アプリのロック。端末の一覧と取り消し、役割と権限、停止と削除、管理者の引き継ぎ、子ども、1人が複数の家族に属する場合。
- 扱わない：電話番号とメールアドレスによる本人の確認（D-11-2）、友だちの追加に当たる手続（D-7-2）、知らない人からの連絡（家族は閉じている）。

### できなければならないこと

- 3-1 家族の作り方
  - R-3-1-1 家族のサーバーの初回の起動で、1回限り・期限付きの管理者の作成の手段（起動の記録に出るリンクと CLI）により、最初の管理者を作れる。
  - R-3-1-2 招待は期限（7日）と回数（1回）を持ち、リンクと QR で渡せ、無効化と作り直しができ、誰が誰を招待したかが記録される。管理者は、招待を出せる構成員を設定できる。
  - R-3-1-3 招待を受けた者は、名前と写真、パスキーの登録、通知の許可の順で、技術を見ずに参加を終えられる。
- 3-2 アカウント
  - R-3-2-1 電話番号とメールアドレスのどちらも要しない。
  - R-3-2-2 表示名、アイコン、背景、ひとこと、誕生日を設定でき、他の構成員の表示名を自分の画面でだけ変えられる。
  - R-3-2-3 役割は管理者と構成員の2段で、会話ごとの権限（グループの作成者）を別に持つ。
- 3-3 ログインと認証
  - R-3-3-1 パスキー（WebAuthn Level 3）を一次の手段とし、回復の手段（回復のコード、管理者による再設定）がある。パスワードは設けない。回復コードとアプリのロックの暗証番号は Argon2id で保護される（第2版）。
  - R-3-3-2 一度ログインすれば長期間ログインし直さずに使え、セッションは安全な Cookie（`__Host-`、Secure、HttpOnly、SameSite=Lax）と更新の仕組みで保たれる。
  - R-3-3-3 新しい端末は、QR をログイン済みの端末で承認する流れ（RFC 8628 に倣う）、または端末が1台の時のパスキーで追加できる。
  - R-3-3-4 アプリのロック（生体認証または暗証番号、時間切れの4段階）をかけられる。
  - R-3-3-5 ログインの失敗の回数が制限される。
- 3-4 端末とセッション
  - R-3-4-1 ユーザーと端末が分かれ、端末ごとに識別子、通知の購読、（採る場合は）鍵を持つ。
  - R-3-4-2 構成員は自分の端末の一覧（名前、最終の利用、IP）を見て個別または全部をログアウトでき、管理者も取り消せる。新しいログインは本人に通知される。
- 3-5 構成の変化
  - R-3-5-1 管理者は構成員を停止（可逆）および削除でき、削除時の本人のメッセージと添付の扱い（残すを既定、消すを選択）が決まっている。本人へ事前に示される。
  - R-3-5-2 管理者を引き継げ、複数の管理者を置ける。管理者の操作は記録され本人に通知される。
- 3-6 子ども
  - R-3-6-1 子のアカウントを親（管理者）が招待して作る流れがある。保護者による管理を設けるかの結論（O-09）があり、設ける場合は子に見える形で制限型である。
- 3-7 複数の家族
  - R-3-7-1 1人が複数の家族のサーバーを使う場合の扱い（O-04）が決まっている。

### 範囲

### できなければならないこと

- 4-1 トーク
  - R-4-1-1 1対1、グループ、自分用メモを作れ、構成員は最初から互いに連絡できる。
  - R-4-1-2 グループは名前とアイコンを持ち、誰でも作成・追加・退会でき、作成者と管理者は構成員を外せる。上限は家族の人数。
  - R-4-1-3 一覧は新しい順で並び、次の操作ができる。
    - 未読の数、ピン留め、お気に入り、並べ替え
    - 通知オフの印、非表示、削除、すべて既読
    - 履歴の書き出し（テキスト）
- 4-2 イベントの記録
  - R-4-2-1 メッセージは不変のイベントとして記録され、サーバーが順序と時刻を付ける。全員の画面で同じ順に並び、二重に届かず、回線が切れている間は端末に保持される。
  - R-4-2-2 種類（テキスト、スタンプ、写真、動画、ファイル、音声、位置、連絡先、通話の記録、システムの知らせ）が決まっている。
  - R-4-2-3 テキストは 10,000 文字まで、1回の送信は 50 件までであり、標準の機能の数値を下回らない。
- 4-3 関係と操作
  - R-4-3-1 次の操作ができる。
    - 返信（引用）
    - 編集（15分以内、「編集済み」）
    - 送信の取消（7日以内。相手の画面に取り消した旨が残り、サーバーから本文と添付が消える）
    - 削除（自分の画面だけ）
    - 転送（複数まとめて）
    - コピー（全文と一部）
    - アナウンス（5件まで）
    - リアクション（6種とすべての絵文字、1人1件）
  - R-4-3-2 長押しのメニュー、右へのスワイプの返信とその代わりの操作、の慣行に合っている。
- 4-4 既読、入力中、メンション
  - R-4-4-1 既読は公開の既読、自分だけの既読、読み終えた位置の3種で記録され、1対1は「既読」、グループは人数を示す。誰が読んだかを示すかの結論がある。
  - R-4-4-2 入力中の表示を備えるかの結論（O-10）がある。
  - R-4-4-3 メンションは本文の一致ではなく欄で記録され、特定の構成員と全員を指定でき、通知オフでも届く。
- 4-5 URL のプレビューと検索
  - R-4-5-1 URL のプレビューは家族のサーバーが取得し、内部の IP の範囲を拒み、短期のキャッシュで、設定で切れる。家族のサーバーの IP が取得先に渡ることは、一覧に示される。
  - R-4-5-2 日本語の全文検索（言葉と日付、トークの中と全体）と、写真・動画、リンク、ファイルの一覧ができる。方式は O-01 の結論による（サーバーの全文検索の拡張、または端末の中の索引）。
- 4-6 グループ向けの機能
  - R-4-6-1 投票（選択肢 10、締切 30日、匿名と複数選択）、ノート（添付 20）、予定（出欠、リマインド、日程の調整）、予約送信（30日先まで）、通知なし送信ができる。
- 4-7 スタンプ
  - R-4-7-1 家族が写真から作り（被写体の切り抜き、文字と落書き、パックの順）、管理者が登録でき、素材は自分の写真か了解を得た写真で、写っている人に通知され削除を求められる。家族の外への書き出しは既定で不可。
  - R-4-7-2 同梱する絵柄の結論（O-06）がある。
- 4-8 ミュートと対処
  - R-4-8-1 構成員ごとのミュート（通知を出さない）と管理者の停止で、ブロックに代えるかの結論（O-11）がある。

## 5. 写真、動画、ファイル、音声、地図

受ける決定は次のとおり。

- D-8-1「写真、動画、ファイルおよび音声を送れる」
- D-8-2「写真と動画は、家族のサーバーで、すべての端末で表示し再生できる形式に変換する」
- D-8-3「写真の撮影の位置その他の情報は、送る時に取り除く」
- D-8-4「送る前に写真を加工できる」
- D-8-5「アルバムを作れる」
- D-8-6「写真、動画およびファイルは、家族のサーバーの容量が続く限り残す」
- D-8-7「動画と元の大きさの写真の自動の取り込みは、回線の種類に応じて構成員が選べる」（送れるもの、変換、EXIF、加工、アルバム、保持、取り込み）
