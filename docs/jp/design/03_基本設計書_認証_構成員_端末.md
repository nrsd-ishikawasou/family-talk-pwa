## 本書の位置付け

- 概要設計書 第3章「認証、構成員、端末」を詳細化する。家族の作り方、招待、アカウントとプロフィール、ログインと認証、端末とセッション、役割、構成の変化、子ども、複数の家族を定め、未決事項 O-09「子どもの利用」を閉じる。O-04 は第1章 13.4 で解消済み、O-11（ブロック）は第4章で閉じる（本章は材料を渡す）。
- 境界の経路は第2章 5.1〜5.4 と 6.2 の表記をそのまま使い、再掲しない。鍵と回復の仕組みは第12章 5.3〜5.6 を参照し、本章は「利用者の操作の流れ」と「サーバーの状態の遷移」を持つ。画面の文言と配置は第10章。
- 準拠：WebAuthn Level 3（W3C Recommendation 2026-08-25）、RFC 8628、NIST SP 800-63B-4（AAL2、§4.2 回復、§3.2.2 制限）、OWASP ASVS 5.0.0 V6・V7、RFC 6265bis、WCAG 2.2 3.3.8、同種サーバーと一般的な通信アプリの慣行（調査資料 準拠の調査 1 §2〜3、準拠の調査 3 §1〜3・5・6）、法務調査 L-2、L-4、L-7、L-14。

## 2. 目的と範囲

### 2.1 受ける要件

概要設計書 第3章の R-3-1-1〜R-3-7-1。対応は 11。

### 2.2 扱うもの・扱わないもの

- 扱う：初回の管理者、招待、参加、アカウントとプロフィール、ログイン（パスキー）、セッション、新しい端末、回復（パスキー）、アプリのロック、失敗の制限、端末の一覧と取り消し、役割、停止・削除・抹消、管理者の引き継ぎ、子ども、複数の家族。
- 扱わない：鍵バンドルと鍵のバックアップの中身（第12章）、API の型（第2章）、画面の文言と配置（第10章）、管理者の画面の全体（第11章）、Android のシェルの認証の画面と鍵保管庫（第9章）。

### 3.2 招待（DD-3-2）

- 属性：`{id, token(ハッシュ), expires_at(7 日), uses_left(1), role: member|admin, display_hint(宛名。任意), child: {is_child, guardians[]}(任意), issuer, created_at, used_by, used_at, revoked_at}`。
- 発行：管理者、または設定「構成員も招待を出せる」が有効な構成員（子ども区分は既定で不可）。1 人が同時に持てる未使用の招待は 20。
- 渡し方：QR（`/i/<token>` の URL）と、リンクの共有（OS の共有）。画面に「この QR は 7 日間、1 人だけ使えます」。
- 無効化・作り直し：発行者と管理者。作り直しは無効化 + 新しい発行。
- 記録：`/admin/invites` に全部（使用済み・無効化済みを含む。1 年で古いものを消す。初期値）。本人の画面には自分の発行分。
- 受け取り側の画面（未認証 `GET /invites/{token}`）：家族の名前とアイコン、招待者の表示名、期限、「参加する」。無効・期限切れ・使用済みは同じ画面で理由（`AUTH-007`。応答の時間を揃える）。

## 4. ログインと認証

### 4.1 パスキーの登録（DD-3-4）

- `PublicKeyCredentialCreationOptions`：`rp: {id: <ドメイン>, name: <家族の名前>}`、`user: {id: <構成員の識別子（バイナリ）>, name: <表示名>, displayName: <表示名>}`、`pubKeyCredParams: [ES256, RS256]`、`authenticatorSelection: {residentKey: "required", userVerification: "required"}`、`hints: ["client-device"]`、`attestation: "none"`、`extensions: {credProps: true, prf: {}}`、`timeout: 300000`、`excludeCredentials: <本人の既存のパスキー>`。
- サーバーは `credProps.rk` と `prf.enabled` を記録する。`prf.enabled` なら、ログインの時に `prf.eval` で鍵を導きコピー (e) を作る（第12章 5.4）。
- 1 人が複数のパスキーを持てる（端末ごと、または同期されたもの）。一覧と削除は設定（削除は再認証）。最後の 1 つは消せない（回復の手段が残っていても。管理者の再設定で消す）。
- 登録できない環境（WebAuthn なし、認証器なし）：「スマートフォンで続ける」の QR。

### 4.2 ログイン（DD-3-4）

- 条件付き UI：ログインの画面の入力欄に `autocomplete="username webauthn"` を置き、`navigator.credentials.get({mediation: "conditional", publicKey: {challenge, rpId, userVerification: "required", allowCredentials: []}})` を開いておく。ボタン「指紋（顔）でログイン」は `mediation: "optional"`。
- WebView（Android のシェル）は条件付き UI が使えないためボタンだけ（第9章。シェルが WebAuthn を有効にする設定を持つ）。
- 成功：`POST /auth/passkey/login/verify` → セッション。端末が既知（Cookie の端末の識別子）なら同じ端末、未知なら新しい端末（未承認。4.4）。
- 失敗：`AUTH-003`。回数は DD-3-9。
- hybrid（PC でスマートフォンを使う）：ブラウザの標準の流れ（QR と BLE）。アプリは何もしない。

### 4.3 セッション（DD-3-5）

- 第2章 4.1 の規則。端末は `X-Session-Expires` を見て、7 日前から次に開いた時に「指紋（顔）で確認してください（安全のため 90 日ごと）」を出し、パスキーで通れば新しいセッション（古いものは失効）。通らない・後回しにすると期限で `session.revoked` → ログインの画面。
- 無操作 30 日：通知を開くだけでも「操作」。
- 端末の取り消し、停止、セッションの署名鍵の交代で失効（第12章 10）。

### 4.4 新しい端末の追加（DD-3-7）

|順|新しい端末|既存の端末|サーバー|
|---|---|---|---|
|1|家族のサーバーの URL を開く → 「端末を追加」→ QR と 8 文字のコード（`/auth/qr/start`）|—|device_code（256 ビット）、user_code（8 文字。I、O、0、1 を除く Base32、4-4 の区切り）、10 分、interval 5 秒|
|2|`/auth/qr/poll` を interval で|設定 > 端末 > 「端末を追加」で QR を読む（または 8 文字を入力）→ アプリのロックの解除（生体認証）→ 承認の画面（新しい端末の種類・名前・IP の国と市・鍵の指紋）→ 「承認」|`/auth/qr/approve`。`slow_down` は interval を 5 秒増やす|
|3|セッションを受け取る（端末は未承認）。端末の鍵を作り `PUT /me/devices/{id}/keys`|新しい端末の公開鍵を本人の署名鍵で署名（`/me/devices/{id}/approve`）、鍵バンドル S と鍵のバックアップの中身を HPKE で `inbox` へ、各トークに Add（Commit）|承認済みに。`device.changed`（本人の全端末、家族の全員）|
|4|`inbox` から鍵バンドルを受け取り、コピー (a) を作る。履歴を同期（第4章）|—|—|

- 期限切れ・拒否：`AUTH-005`。新しい端末は「承認されませんでした」。
- 端末が 1 台しかない（既存の端末が手元にない）：パスキー（同期されたもの）でログイン → 未承認 → 鍵バンドルの回復の 4 段（第12章 5.4）：(e) PRF があれば即、(c) 家族に頼む、(b) 回復コード、(d) 家族回復鍵。
- 子ども区分の端末の追加は保護者の端末が承認する（本人の既存の端末でも可だが、保護者に知らせ）。

### 4.5 再認証を要する操作

端末の承認、端末の取り消し（他の端末）、パスキーの追加と削除、回復コードの再発行、鍵の作り直し、抹消、別名の削除以外の設定の変更は要しない。管理者の操作（停止、削除、役割、引き継ぎ、家族回復鍵のカードの作り直し、設定の変更）、保護者の設定。再認証は「パスキー（UV）」または「アプリのロックの解除（生体認証・暗証番号）から 5 分以内」。

### 4.6 回復（パスキーを失った）

|状況|手段|
|---|---|
|パスキーが同期されている（同じ OS のアカウントの新しい端末）|そのままログイン（4.2）→ 端末は未承認 → 鍵バンドルの回復|
|パスキーを失い、既存の端末がある|既存の端末で新しい端末を承認（4.4）→ 新しい端末でパスキーを追加|
|パスキーも既存の端末もない|管理者が `/admin/users/{id}/reset-link`（24 時間、1 回）を発行し、本人に渡す（対面、別の経路）。本人はリンクでパスキーを登録 → 未承認の端末 → 鍵バンドルの回復（家族 → 回復コード → カード）。管理者の操作は記録し本人と全員に知らせ|
|子ども|保護者が管理者に頼む（保護者が管理者ならそのまま）|

- 鍵バンドルの回復は第12章 5.4。回復のたびに本人の全端末と管理者に `recovery.used`（NIST SP 800-63B-4 §4.2.5）。

### 4.7 アプリのロック（DD-3-8）

|方式|iPhone / PC|Android（シェル）|
|---|---|---|
|生体認証・画面のロック|WebAuthn `get()`（UV 必須、`allowCredentials` は本人のパスキー）をロックの解除に使う。失敗は OS の画面|OS の認証の画面（BiometricPrompt、端末の資格情報）。シェルが WebView に解除を伝える（第9章）|
|暗証番号（6 桁）|端末の中に Argon2id（m=64 MiB、t=3、p=4。WASM）のハッシュ。5 回失敗で 1 分、以後倍、10 回で端末のコピーと鍵を消してログアウト（取り消しの知らせを本人の他の端末へ）|同じ|
|時間切れ|即時 / 1 分 / 5 分 / 1 時間 / オフ（既定）|同じ|
|かかる範囲|画面の表示の前。通知の表示は影響しない（内容を表示しない設定は第7章）。通話の着信の応答はロックの外（応答してから画面を開く時にロック）|同じ|

- ロックは端末ごとの設定（サーバーに同期しない）。
- 家族で端末を共有する場面（T-10）：手順書で「1 人 1 アカウント」と「共有の PC はロックを即時に」を勧める。

## 5. 端末とセッション（DD-3-6）

### 5.1 端末の状態

```
未登録 → 未承認（セッションあり。鍵の運搬と自分の端末の経路だけ）→ 承認済み（全部）
承認済み → 取り消し済み（セッション・購読・鍵の失効。コピー (a) の削除、全 leaf の Remove）
未承認 → 期限切れ（7 日で削除）
```

- 承認済みの端末の leaf が 90 日現れない：他の端末が Remove し、端末は「休眠」になる（セッションは残る）。次に開いた時は新しい端末と同じ流れで Add（鍵バンドルは端末にあるので承認は不要）。

### 5.2 一覧と取り消し

- 本人：設定 > 端末。各端末に名前（変更可）、種類、最終の利用、IP の国と市、「この端末」の印、承認の状態、購読の有無、鍵の指紋。操作：「ログアウト」（個別）、「他のすべての端末からログアウト」、名前の変更。取り消しは再認証。
- 管理者：`/admin/users/{id}/devices/{did}` で取り消し。本人と全員に知らせ。
- 取り消された端末：`session.revoked` を受けて保存を消しログインの画面へ。届かなければ次の要求で `AUTH-002`。
- 新しいログイン・新しい端末の知らせ：`device.changed` と通知（本人の他の端末。子どもは保護者にも）。内容：端末の種類・名前・時刻・場所（国と市）。「心当たりがなければ取り消してください」の導線。

### 5.3 IP と場所

- 生の IP は 28 日で消す別の表（第12章 11）。一覧に出すのは国と市（端末の中の地理のデータで求める。外部に問い合わせない）。

## 7. 役割と権限（DD-3-10）

|役割|できること|
|---|---|
|構成員|自分のトークの作成と参加、送信、自分の端末と設定、招待（設定で許された時）、自分の抹消|
|管理者|構成員の全部 + `/admin/*`（設定、構成員の停止・削除・役割、端末の取り消し、再設定のリンク、招待の記録、容量、バックアップ、更新、地図、家族の名前、カードの作り直し、引き継ぎ）。他人のトークの閲覧はできない（設計計画書 D-13-6）|
|保護者（関係）|子の時間帯・リンクの確認・端末の追加の承認・招待の可否の設定、子の新しい端末の承認、子の知らせの受信|
|トークの作成者（第4章）|構成員を外す、トークの設定|

- 管理者は構成員でもある（自分のトークは構成員として読む）。
- 停止中の構成員は役割を失わない（再開で戻る）。

## 8. 構成の変化（DD-3-11、DD-3-12）

### 8.1 停止と再開

|操作|サーバー|本人の端末|家族|
|---|---|---|---|
|停止（`/admin/users/{id}/suspend`。再認証。理由は任意）|状態を「停止」。セッション・購読を失効、端末の鍵を失効（公開鍵とコピー (a) は残す。90 日で他の端末が leaf を Remove）。招待の発行を無効|`session.revoked`（reason: suspended）。画面「停止されています。管理者：○○」|システムの知らせ「○○さんは停止中です」（家族全員のトーク）。本人に通知（届く経路があれば）|
|再開|状態を「通常」。本人はログインし直し（パスキー）、端末は未承認から（鍵バンドルは端末に残っていればコピー (a) で即）|—|知らせ|

### 8.2 削除

- `DELETE /admin/users/{id}?erase_content=false|true`（再認証）。確認の画面に「○○さんの投稿と写真は残ります（消えます）。○○さんはログインできなくなり、鍵は無効になります。取り消せません」。
- 処理：停止 + 全トークから leaf の Remove（管理者の端末が Commit。他の構成員の端末でも可）+ 構成員の状態「削除」。`erase_content=true` なら本人のイベントを削除済みの印に（第12章 9）。鍵バンドルのコピー・秘密分散の断片・鍵のバックアップは残す（本人の求めによる抹消ではないため。再参加はできないので実質読めない。第12章 9 の「抹消」とは別）。
- 本人には事前に示す：参加の時の「データの取扱いについて」に「管理者はあなたを削除でき、その時あなたの投稿は既定で残ります」。
- 削除された構成員の表示名は「（退出した人）」ではなく最後の表示名のまま残す（家族の記録）。

### 8.3 抹消（本人の求め。DD-3-15）

- 設定 > アカウント > 「このサーバーから抹消する」→ 失うものの一覧 → 再認証 → 24 時間の猶予（取り消し可。全端末に知らせ）→ 実行（第12章 9 の抹消）。
- 子ども区分：保護者の承認を要する（保護者の端末に求めが届き、`POST /me/guardian/approvals/{id}` で承認する。第2章 5.3）。
- 管理者が本人なら、先に別の管理者に引き継ぐ（最後の 1 人は抹消できない。`MEM-003`）。

### 8.4 管理者の引き継ぎと複数の管理者

- 付与：`/admin/users/{id}/role`（再認証）。相手に知らせ。解除も同じ。
- 引き継ぎ：`/admin/transfer`（相手を指名 → 相手の端末に求め → 相手が `POST /me/transfer/{id}/accept` で承認すると相手が管理者になり、自分は構成員に）。自分が最後の 1 人の時はこれだけが自分を外す手段。
- 最後の 1 人の管理者は、自分の停止・削除・抹消・役割の解除ができない（`MEM-003`）。
- 全管理者の不在（第1章 21）：手順書に「管理者を 2 人以上」「カードを別の大人に」。初回（3.1 の 9）と、管理者が 1 人の間は管理者の画面にバナーで案内。

## 9. 子ども（DD-3-13。O-09 の結論）

### 9.1 区分と保護者

- 区分：招待の時に「子ども（16 歳未満）」を選ぶか、誕生日から自動。誕生日が入れば誕生日が正。
- 保護者：招待した者が既定。管理者が追加・変更できる（保護者は管理者でなくてよい。複数可）。子の画面の設定 > アカウントに「保護者：○○、○○」を常に表示する。
- 16 歳の誕生日で時間帯とリンクの確認が自動で解除され、18 歳で区分が外れる（本人と保護者に知らせ）。誕生日がなく申告だけの場合、2 年ごとに保護者に「まだ 16 歳未満ですか」を問う。

### 9.2 保護者が設定できること（制限型）

|設定|中身|子の画面|
|---|---|---|
|利用の時間帯|例：21:00〜7:00。その間、通知を止め（通話の着信は止めない）、アプリを開くと「おやすみの時間です」の案内（閉じれば使える。遮断しない）|案内に「保護者の設定」と示す|
|外部リンクの確認|本文の URL を開く前に「家族の外のページを開きます」の確認。プレビューは出る|確認の画面|
|端末の追加の承認|子の新しい端末の承認は保護者の端末で（4.4）|承認を待つ画面|
|招待の発行|既定で不可。保護者が許せる|招待のボタンが出ない|

- 記録の閲覧、連絡の相手の制限（家族は閉じている）、位置の追跡は置かない。
- 保護者への知らせ：子の新しい端末・ログイン、停止、保護者の変更、抹消の求め、16 歳・18 歳の解除。

### 9.3 同意

- 16 歳未満の子の参加（個人情報の取扱いの同意）は、招待した保護者の操作をもって法定代理人の同意とみなす（令和 8 年改正の個人情報保護法の趣旨。法務調査 L-4）。参加の画面 6 の明示は子にも示す（子にも分かる文言。第10章）。

## 10. 複数の家族（DD-3-16。O-04 の確認）

- 家族のサーバーごとにアカウント・パスキー・鍵バンドル・端末の登録が別。同じ人が 2 つの家族に属しても、サーバーの間に関係はない。
- iPhone と PC：家族ごとに別のホーム画面のアイコン（別のオリジン）。Android：シェルが家族の一覧を持ち切り替える（通知は全部から。第9章）。
- 家族回復鍵のカードも家族ごと。

脅威との対応（第1章 11.2）：T-1（招待の流出）は 3.2（7 日・1 回・発行者の確認・参加の知らせ）；T-2（端末の紛失）は 4.7、5.2；T-10（アカウントの共有）は 4.7、手順書；T-8（否認）は端末の識別子と記録。

## 12. 失敗の扱い

|失敗|扱い|
|---|---|
|管理者の作成のリンクの期限切れ|CLI で作り直す（`app admin create-link`）。設置の道具の画面にも案内|
|パスキーの登録に失敗（認証器なし、利用者が拒否）|「スマートフォンで続ける」の QR。拒否なら参加できない（パスキーは必須）。理由を 1 文で|
|招待の token が無効・期限切れ・使用済み|同じ画面で理由。「招待した人に作り直してもらってください」|
|QR の承認が 10 分で来ない|新しい端末は作り直しのボタン。既存の端末の承認の画面は閉じる|
|承認の後に鍵バンドルが届かない（既存の端末が転送の途中で切れた）|新しい端末は「鍵を待っています」。既存の端末は次にオンラインの時に転送を再開（inbox に未送信を保持）。10 分経てば新しい端末に回復の 4 段を案内|
|セッションの期限切れ（絶対 90 日）で再認証を後回しにし続けた|期限で `session.revoked`。ログインの画面（パスキー）。鍵バンドルは端末にあるので履歴は残る|
|暗証番号を 10 回誤る|端末のコピーと鍵を消しログアウト。本人の他の端末に「○○（端末名）がロックの失敗で初期化されました」。再ログインは新しい端末の流れ|
|管理者の再設定のリンクが第三者に渡った|リンクは 24 時間・1 回。使われれば本人の全端末と全員に知らせ（`recovery.used`）。本人が心当たりなければ管理者が端末を取り消し|
|子どもの時間帯の設定の間に緊急の連絡|通話の着信とメンションの通知は止めない（9.2）。開けば使える|
|最後の管理者が亡くなった|第1章 21 の既知の制約。カードが別の大人にあれば、その人が `/family/recovery-key/use` で自分の鍵バンドルを回復できるが管理者にはなれない。管理者の作成は CLI（サーバーの機械の操作）でしかできない → 手順書「サーバーの機械にログインできる人を 2 人」|
|同期されたパスキーで他人の端末からログインされた（OS のアカウントの共有）|端末は未承認で鍵バンドルがなければ読めない。新しいログインの知らせで本人が気づき取り消す。手順書で OS のアカウントの共有を避けるよう案内|

## 13. 用語

|用語|意味|
|---|---|
|パスキー|WebAuthn の discoverable credential。指紋・顔・画面のロックで使う|
|条件付き UI|入力欄のオートフィルにパスキーを出す仕組み（`mediation: "conditional"`）|
|hybrid|PC のブラウザがスマートフォンの認証器を QR と BLE で使う仕組み|
|user_code|RFC 8628 の、利用者が読む短いコード。本章では 8 文字|
|未承認の端末|セッションはあるが本人の署名鍵による承認がなく、鍵バンドルを持たない端末|
|保護者|子ども区分の構成員の制限を設定する構成員（関係）|
|子ども区分|16 歳未満の構成員|

## 14. 本章で宣言する既知の制約

|番号|既知の制約|理由|緩和|
|---|---|---|---|
|H-3-1|パスキーが必須のため、WebAuthn のない環境（古い PC のブラウザ、認証器も hybrid もない端末）では参加もログインもできない|パスワードを設けない（DD-3-4）|最低要件（第14章 4）の全端末は対応。QR の承認で新しい端末を加えられる（ログインは既存の端末が代わりに承認）|
|H-3-2|家族で 1 台の端末を共有すると、他人として送れる|端末の共有は設計の外（T-10）|アプリのロック、手順書|
|H-3-3|同期されたパスキーは OS のアカウントを共有する他人の端末でもログインが通る|パスキーの同期は OS の仕組み|未承認の端末は読めない。新しいログインの知らせ|
|H-3-4|保護者の時間帯は遮断ではなく案内であり、子が無視すれば使える|緊急の連絡を妨げない（DD-3-13）|OS のスクリーンタイム等を手順書で案内|
|H-3-5|管理者の再設定のリンクは本人への受け渡し（対面・別の経路）に依存する|メールも電話番号もない|全員への知らせ|
|H-3-6|誕生日を入れない子どもの区分は申告に依存する|本人の確認の手段がない|2 年ごとの保護者への確認|

［要実測］：iOS のホーム画面の Web アプリでの条件付き UI と hybrid；iOS 18 の PRF；WebView の WebAuthn（第14章 7.1 の設定）；Linux の PC での hybrid；Argon2id（64 MiB）の端末での所要時間（アプリのロックの暗証番号）。

## 15. 章の依存

- 本章が与える：参加と端末の流れ（第10章の画面、第9章のシェル）、保護者の設定（第4章のリンクの確認、第7章の時間帯）、停止・削除の処理（第4章の leaf の Remove、第11章の管理者の画面）、再認証の規則（全章）。

## 16. 他の章・概要設計書・設計計画書への訂正

- 設計計画書 第17章 O-09：第3章で解消（制限型の保護者の仕組み）。O-04 は第1章で解消済み。
- 設計計画書 第11.3節「ログインの方式は設計書で定める」：パスキーのみ、パスワードなし（本章 DD-3-4）。第11.5節「退出した構成員の過去のメッセージ」：既定で残す（本章 DD-3-11、第12章 9）。
- 概要設計書 第3章 R-3-3-1「パスワードを要する場合は Argon2id」：パスワードは設けない。Argon2id はアプリのロックの暗証番号と回復コードの鍵の導出に使う。
- 概要設計書 第10章：参加の 3 画面、承認の画面、回復の 4 段の画面、保護者の表示、「データの取扱いについて」の子ども向けの文言を画面の要件に加える。
- 概要設計書 第7章：子どもの時間帯（通知を止める。通話とメンションは止めない）を通知の規則に加える。
- 概要設計書 第4章：外部リンクの確認（子ども）、家族全員のトークへの Add を招待者の端末が行うこと、別名の表示。
- 第2章 5.1：`/setup/admin/{token}` の GET が「設置の状態が初回でなければ 404」。5.2：`/auth/qr/start` の user_code は 8 文字（I、O、0、1 を除く）。5.3：`/me/erase` に子どもの保護者の承認。5.10：`/admin/users/{id}/guardians`（保護者の設定）と `/admin/users/{id}/child`（区分）を追加（第2巡）。エラーコード表に `MEM-006`（保護者の承認待ち）、`MEM-007`（子ども区分の操作の不可）を追加。
- 第12章 5.5：承認の順序（署名 → 鍵バンドル → 鍵のバックアップ → Add）は本章 4.4 と一致（変更なし）。
