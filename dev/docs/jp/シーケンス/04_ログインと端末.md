</details>
- セッションの静かな作り直し（第3章 4.3）：
  - `X-Session-Expires` の 7 日前に WC `Session.state = expiring` になる
  - 次に開いた時に UI が `credentials.get`（UV）、`POST /auth/passkey/login/verify`、ID `Sessions::Rotate`（古いものは失効）の順に行う
  - 後回しにし続ければ期限で `session.revoked` になり、ログインの画面に戻る

## S-04b 新しい端末の追加：QR の承認（第3章 4.4）

![シーケンス図：S-04b 新しい端末の追加：QR の承認（第3章 4.4）（画像を開くと原寸で読める）](../fig/シーケンス図/04_ログインと端末_2.png)

<details><summary>図の元の文（mermaid）</summary>

```mermaid
sequenceDiagram
  participant N as 新しい端末（web-ui/web-crypto/web-sync）
  participant BD as srv-boundary
  participant ID as srv-identity
  participant KY as srv-keys
  participant E as 既存の端末（web-ui/web-crypto/web-sync）
  N->>BD: POST /auth/qr/start {kind, name}
  BD->>ID: QrFlow::Start（B-068）で device_code、user_code（8 文字）、/d/<code>、10 分、interval 5 を作る
  N->>N: QR と 8 文字を表示。POST /auth/qr/poll を interval で（AUTH-005 pending。slow_down なら interval +5）
  E->>E: 設定 > 端末 >「端末を追加」。QR を読むか 8 文字を入れ、AppLock::unlock（web-shell B-343：生体認証）
  E->>BD: GET /auth/qr/{user_code}（G-13。ID QrFlow::Info：種類、名前、IP、指紋）
  E->>BD: POST /auth/qr/approve {user_code}（再認証 AUTH-006）
  BD->>ID: QrFlow::Approve（B-068。子どもは保護者 MEM-006）の後に Sessions::Issue（新しい端末。未承認）と Devices::Register
  N->>BD: POST /auth/qr/poll で Cookie と {approved: false} を受ける
  N->>WX: DeviceKeys::create の後に PUT /me/devices/{id}/keys（fdev/1、未承認）
  BD-->>E: イベント device.changed{added}（本人の全端末）
  E->>BD: GET /users/{me}（新しい端末の fdev）
  E->>WX: Recovery::approveDevice（B-222）：user_sig で POST /me/devices/{did}/approve。S を HPKE で inbox へ。KeyBackup::transferTo（B-223。復号済みの中身を分割して inbox）
  BD->>KY: DeviceKeys::Approve（B-081）で ID の Devices を approved に。Inbox::Put × n（B-085）
  E->>WS: 各トークに Mls::addMembers（新しい端末の KeyPackage。S-03d と同じ Commit）
  BD-->>N: device.changed{approved}、device.inbox{count}
  N->>BD: GET /me/inbox?since
  N->>WX: ToDevice::open、Recovery::fromInbox、KeyBundle::fromS、Copies::putDevice（コピー (a)）の順。localStorageKey も
  N->>N: 履歴の同期（S-04d）
  BD-->>E: device.changed{added}「新しい端末が追加されました」（本人の全端末。子どもは保護者にも）
```

</details>
- 失敗：
  - 10 分で承認が来ない：AUTH-005 expired。新しい端末は作り直し、既存の承認の画面は閉じる
  - 承認の後に鍵バンドルが届かない（転送の途中で切れた）：N は「鍵を待っています」。E は次にオンラインの時に `inbox` の未送信を再開する（web-crypto `Recovery.approveDevice` は冪等。未送信は E の IndexedDB `queue` に積む：G-14）
  - 10 分経てば N に回復の 4 段を案内する

## S-04e アプリのロック（第3章 4.7）

- web-shell `AppLock`（B-343）：画面の表示の前。生体認証はシェル `biometricUnlock`（and-keystore B-402）または WebAuthn `get()`（UV）。暗証番号は `AppLockHash::verify`。失敗 5 回で 1 分、以後倍、10 回で `Db::wipe` と `DELETE /me/devices/{me}`（自分の端末の取り消し）。本人の他の端末に `device.changed(revoked)` と通知「{device}（端末名）がロックの失敗で初期化されました」。通知の表示と着信の応答はロックの外。

## 抜け

- なし。この入口で見つけた物は直した（全体実装設計書 11.1）。
  - G-13：`GET /auth/qr/{user_code}`（第2章 5.2、srv-identity `QrFlow::Info`）。IP の国と市は端末の中の地理のデータで求めるため、応答は生の IP
  - G-14：承認の時の転送の再開は、既存の端末の IndexedDB `queue` の `kind: inbox`（web-sync.md）
  - 回復コードの再発行：`PUT /me/recovery-code`（G-11）
  - PRF のコピーの取得：`GET /me/keybundle/{kind}/{target}`（規則 prf_or_approved。第2章 5.4）
