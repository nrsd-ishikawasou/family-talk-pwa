<details><summary>図の元の文（mermaid）</summary>

```mermaid
sequenceDiagram
  participant N as 新しい端末（web-ui/web-crypto/web-sync）
  participant BD as srv-boundary
  participant ID as srv-identity
  participant KY as srv-keys
  participant E as 既存の端末（web-ui/web-crypto/web-sync）

  E->>E: 設定 > 端末 >「端末を追加」→ QR を読む / 8 文字 → AppLock::unlock（web-shell B-343：生体認証）
  E->>BD: GET /auth/qr/{user_code}/info（抜け G-13：承認の画面に出す種類・名前・IP の国と市・指紋の経路が無い）
  E->>BD: POST /auth/qr/approve {user_code}（再認証 AUTH-006）
  BD->>ID: QrFlow::Approve（B-068。子どもは保護者 MEM-006）→ Sessions::Issue（新しい端末。未承認）→ Devices::Register

  E->>BD: GET /users/{me}（新しい端末の fdev）
  E->>WX: Recovery::approveDevice（B-222）：user_sig → POST /me/devices/{did}/approve；S を HPKE で inbox；KeyBackup::transferTo（B-223。復号済みの中身を分割して inbox）
  BD->>KY: DeviceKeys::Approve（B-081）→ ID Devices（approved）、Inbox::Put × n（B-085）

  N->>BD: GET /me/inbox?since

  N->>N: 履歴の同期（S-04d）
  BD-->>E: device.changed{added}「新しい端末が追加されました」（本人の全端末。子どもは保護者にも）
```

</details>
- 失敗：10 分で承認が来ない → AUTH-005 expired。新しい端末は作り直し、既存の承認の画面は閉じる。承認の後に鍵バンドルが届かない（転送の途中で切れた）→ N は「鍵を待っています」。E は次にオンラインの時に `inbox` の未送信を再開（web-crypto `Recovery.approveDevice` は冪等。inbox の未送信は E の IndexedDB `queue` に積む：抜け G-14）。10 分経てば N に回復の 4 段を案内。

## S-04e アプリのロック（第3章 4.7）
- web-shell `AppLock`（B-343）：画面の表示の前。生体認証はシェル `biometricUnlock`（and-keystore B-402）または WebAuthn `get()`（UV）。暗証番号は `AppLockHash::verify`。失敗 5 回で 1 分、以後倍、10 回で `Db::wipe` + `DELETE /me/devices/{me}`（自分の端末の取り消し。本人の他の端末に `device.changed(revoked)` と通知「○○（端末名）がロックの失敗で初期化されました」）。通知の表示と着信の応答はロックの外。

## 抜け
- G-13：承認の画面に出す「新しい端末の種類・名前・IP の国と市・鍵の指紋」を既存の端末が取る経路が第2章 5.2 に無い。`GET /auth/qr/{user_code}` （本人。承認の前の情報）を足す。IP の国と市は端末の中の地理のデータで求めるため、応答は生の IP（エンベロープから開いた値）。
- G-14：承認の時の鍵バンドルと鍵のバックアップの転送（inbox への PUT の列）が途中で切れた時の再開のため、既存の端末は未送信を IndexedDB `queue` に「inbox の項目」として積む（web-sync.md `queue` の `kind` に `inbox` を足す）。
- 回復コードの再発行の経路は G-11（`PUT /me/recovery-code`）。
