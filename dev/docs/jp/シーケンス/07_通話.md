- 拒否：B `decline` → `POST /calls/{id}/decline` → CL `Decline`：call.state{declined}、`Timeline::CallEvent(declined)`、`CallRinger::Stop`。
- 取消：A `cancel` → `POST /calls/{id}/end`（ringing のまま）→ cancelled。
- 不在：`RingTimer::Fire`（60 秒）→ missed：call.state{missed}、`CallEvent(missed)` を双方、相手に `kind: call_end` の通知「不在着信」。
- Android の応答：AC `answer` → `CallService::start`（5 秒以内）→ CallStyle 通話中 → `MainActivity` 前面 → bridge `callAnswered{call_id}` → web-calls `answer`。拒否：bridge `callDeclined` → `/decline` → `disconnect`。

## S-07d 通話中の別の着信、着信を受けない、同時の発信（第6章 4.1、第2章 11）
- 別の着信：CL `Calls::Start` が `IsBusy(callee)` → 発信者に CALL-003、相手には不在の記録と「通話中に ○○さんから着信」の知らせ（RM `SystemEvent`）。シェルには届かない。
- 着信を受けない：`Users::Settings` の `receive_calls = false` → CALL-005（記録なし）。
- 同時の発信：同じトークに進行中があれば CALL-002 で既存に合流（RoomLock の中で `InProgressOf`）。

## 抜け
- 1 対 1 の `End` の即時の終了で CL が `SfuAdmin::DeleteRoom` を呼ぶことは srv-calls.md の `End` の注記に無い → srv-calls.md `Calls::End` に「dm は SfuAdmin.DeleteRoom（B-009）でルームを閉じ、Webhook の room_finished を待たずに CallEvent(ended)」を足す（本シーケンスで足す）。
- 通話の鍵のイベント（`ft.content.call_key/1`）は通話の参加者でない構成員の端末にも MLS で届く（トークのグループ）。受け手は通話に参加していなければ keyring に入れるだけ（web-calls `Keys::onKeyEvent` は `CallSession.state` が idle なら保持だけ）。仕様どおり（第12章 5.11）。
- iPhone の `call_end` の通知の置き換えと「不在着信」の通知は S-08。
