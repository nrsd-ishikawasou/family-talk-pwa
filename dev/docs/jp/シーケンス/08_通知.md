```mermaid
  alt message
    WP->>BD: GET /rooms/{room_id}/events/{event_id}

    end

    WP->>WP: Notify::show（3 択：名前と本文／名前のみ／なし。tag = room_id、同じトークは「n 件の新着」。iPhone は同じ tag の前の通知を閉じてから出す。PC は actions reply）
    WP->>OS: showNotification、setAppBadge(app_badge または /rooms の合計)
    opt 宣言型
      Note over WP,OS: SW が時間内に showNotification したので提案の通知は出ない。出せなければ OS が提案の通知を出す
    end
    alt 10 秒で終わらない
      WP->>WP: Notify::generic
    end
  else call
    WP->>BD: GET /calls/{call_id}（ringing でなければ call_end と同じ表示）
    WP->>OS: Notify::showCall「（名前）さんから着信」「応答するには開いてください」（tag call:<id>。3 回の push のたびに出す。iPhone は 3 件が並び毎回鳴る）
    WP->>WS: Channel で画面に問い、前面なら web-calls の呼び出し画面（Ringtone）
  else call_end
    WP->>OS: Notify::closeCall（call:<id> の通知を閉じる。iPhone は表示から 30 秒を待つ）の後に Notify::endCall（missed は「不在着信」、他は音なしの「終わりました」）
  else notice
    WP->>OS: Notify::showNotice
  end
  OS->>WP: notificationclick で clients.matchAll。あれば focus して /r/<room_id>、無ければ openWindow
  opt PC の action=reply
    WP->>WS: Reply::fromNotification から SendQueue::enqueue（既読は付けない）
  end
```

</details>
- 必ず 1 回 `showNotification`（iOS の規則）。SW の寿命は短い前提。

## S-08f 知らせ（`notice`。第7章 9）

- 発行：PS `Notices::Emit(kind, level, text_key, params, audience)`（B-147）。種類は第7章 9 の表の全行。
  - `notices` 表に置く（重複の抑止 (kind, key, day)）。宛先を構成員へ解き `notice_recipients` に置く（srv-identity `Users::List`、`Guardians::Of`）
  - feed `notice`（self、all、admins、guardians）と、宛先の端末のうち開いていない物へ `kind: notice` の通知（event_id は知らせの id）
  - SW は `GET /me/notices/{id}` で中身を取り、第10章 9.4 の文言で出す
  - トークに残るものは RM `FamilyRoom::Flow` で `ft.event.system/1`
- 受け：web-sync `Notices::onNotice` が IndexedDB `notices` に置き、web-ui の知らせの一覧とバナーに出す。シェルは `Notifier::notice`。
- 取り直し：`GET /me/notices`（第2章 5.3。全差分の取り直し。web-sync `Sync::fullResync`）は BD から PS `Notices::ListMine`（B-147）。`notice_recipients` を本人で引く。

## 抜け

- なし。この入口で見つけた物は直した（全体実装設計書 11.1）。
  - G-06：`DecryptHost` と `/notify.html` の JS ブリッジの 4 つ（`push`、`notifyResult`、`reply`、`replyDone`）。`replyDone` の後の通知の更新は第9章 5 と and-push `DecryptHost::onReplyDone`
  - G-07：`pushEndpoint`（web-push `Subscription::onShellEndpoint`）
- バッジの値は第7章 5.3 と一致する。
  - iPhone：宣言型の `app_badge`（サーバーが `Badge::Count`）
  - Android：`notifyResult.badge`（ウェブアプリが `/rooms` から計算）を and-push `Notifier::badge(setNumber)` へ
