## S-11b 構成員・招待の記録・トーク（第11章 8）
- 構成員の一覧 `GET /admin/users`（AD `AdminApi::Users`：状態、端末の数、最終の利用、容量は MD `Quota::Usage.by_user`）。操作（停止・再開・削除・端末の取り消し・再設定のリンク・役割・保護者・子ども）は S-10 の各流れ。再設定のリンク：`POST /admin/users/{id}/reset-link` → ID `ResetLink::Create`（B-069）→ 画面に表示して本人へ別の経路で渡す。
- 招待の記録 `GET /admin/invites`（ID `Invites::ListAll`）、無効化 `DELETE /invites/{id}`。
- トーク `GET /admin/rooms`（識別子、種類、人数、容量。名前は見えない）、空のグループの削除 `DELETE /admin/rooms/{id}` → RM `Rooms::Delete`。

## S-11e 地図、家族、廃棄の案内、スタンプ（第11章 8）
- 地図：`GET /admin/maps` → MD `Maps::Current`。`POST /admin/maps {region}` → AD が ST `Jobs::Enqueue(maps_update)` → srv-worker `MapsUpdateHandler`（S-12）。
- 家族：`PATCH /admin/family {name, icon}` → ID `Families::Update`（B-060）→ RM `SystemEvent` + `ft.content.room_settings/1` は管理者の端末が家族全員のトークへ送る（S-05a）。カードの作り直し、引き継ぎは S-10g、S-10e。
- 廃棄：`GET /admin/disk/dispose` → AD `AdminApi::DisposeGuide`（手順の文。実行は `ft disk dispose`：S-13）。
- スタンプの登録：管理者も構成員と同じ流れ（S-06e）。
- データの取扱い（第12章 7.2）：管理者の名前は ID `Families::Disclosure` が `users` の admin から埋める。管理者が変われば自動で変わる。

## 抜け
- G-01（既出）：ログの要約の経路。
- 管理者の操作の知らせは「本人 + 全員」（DD-12-16）。本人がいない操作（設定の変更）は全員だけ：srv-admin.md `Audit::Record` の注記に「対象の構成員がいない操作は audience = all」を足す（本シーケンスで足す）。
