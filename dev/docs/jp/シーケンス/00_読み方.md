# シーケンス（入口ごとに、クライアント側とサーバー側をまたいで、どこの何が呼ばれるかを全ルート追う）

- 入口 = 利用者の操作（ウェブアプリの画面、シェルの画面）、家族のサーバーの起動、裏の仕事、通知の受信、通話の着信、管理者の操作、`ft` の操作、運営者の操作。番号と入口の一覧は全体実装設計書 11 の表が正。
- 参加者（participant）はブロックの名前（略号は下の表）。矢印の名前は各ブロックのページの公開操作（`Block::op`、番号 B-）。ページに無い操作を要した時はページに足してから書く（それが抜け）。境界を越える矢印は第2章の経路（`POST /rooms/{id}/events` 等）とイベントの `type` で書く。
- 失敗の分岐は、仕様の「失敗の扱い」の節と第2章 9.2 のエラーコード表に行がある事象だけを書く。
- 抜け（追って見つけた、ページにも仕様にも無いもの）は各ファイルの末尾「抜け」に、直した先（ページ・仕様の節）と一緒に書く。直さずに残さない。第2章・第9章への改訂は層9 の終わりにまとめて行う（全体実装設計書 11.1 の G- と合わせて）。
- 各シーケンスは試験設計書 第3章の T-L1（サーバー側の分）と T-L3／T-L4（クライアント側の分）に 1 対 1 で対応する（全体実装設計書 11 の表）。
