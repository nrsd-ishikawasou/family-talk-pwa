## 本書の位置付け

- 試験設計書 第5章 1 の「L6（受け入れ、性能、見やすさ、運営）」と「T-M（実測）」の記録の置き場である。全体実装設計書 6.1 の L6 の行と 6.5 から参照される。
- 判定の基準は試験設計書 第3章（6〜12）が正である。本書は記録の欄だけを持ち、判定の基準を写さない。
- 記録には家族の情報（名前、本文、写真、発言）を書かない。試行は率と所要だけを書く（試験設計書 第5章 1）。
- 欄は、その試験を回す作業の単位が足す。今あるのは T-L6-09（iPhone の実機の測り。基本設計書 第14章 11.6）だけである。

## 1. 共通の欄

各表の行は 1 回の試しで、次の欄を持つ。

|欄|書くこと|
|---|---|
|日付|試した日（JST）|
|記録した者|担当開発者の名前か、家族の外の試す人の呼び名（個人を特定する情報は書かない）|
|端末|機種と記憶の容量（例：iPhone 11、64 GB）。試験設計書 第4章 E-4 のどちらの台か|
|OS の版|設定の「情報」の版と build（例：18.1、22B83）|
|アプリの版|確かめのページの `page_rev`、または本システムの版|
|項目|試験設計書の項目の番号と記号|
|回|同じ版・同じ項目の何回目か|
|結果|試験設計書の判定の欄の言葉（可、不可、数値）|
|記録の置き場|結果の JSON などのファイル（3）|

## 2. T-L6-09 iPhone の実機の測り

手順は `web/probe/README.md` の「実機の測りの手順」。判定は試験設計書 T-L6-09 の判定の欄。版ごとに (a)〜(g) を 3 回（push の項目は 1 回 10 通）行う。結果が設計書の前提を動かす時（例：(b) と第12章 5.8、H-12-22）は、T-L6-09 の判定の欄のとおり設計書を改める。

|日付|記録した者|端末|OS の版|アプリの版|項目|回|結果|数値|記録の置き場|
|---|---|---|---|---|---|---|---|---|---|
|（未実施。iPhone の入手を待つ）|—|—|—|—|—|—|—|—|—|

数値の欄に書くこと（項目ごと）は次のとおり。

|項目|数値の欄|
|---|---|
|(a) 端末の鍵の読み出し|復元の種類（暗号化しないバックアップ、初期化と復元）ごとの開いた時の `state`（none、ok、unreadable）と、unreadable の時の「消して作り直す」の `steps`|
|(b) ロック中の Service Worker|ロックの直後と 5 分後の各 10 通について、SW の記録の行の数と、そのうち `key` が `ok` の数|
|(c) PRF|3 回の `prf_first_sha256_8` が同じか（同じなら「同じ」、違えば 3 つの値）|
|(d) Web Push|旧来の形と宣言型の各 10 通について、通知の数（1 通ごと）、バッジの数、SW の記録の `form`|
|(e) 着信|鳴った回数、`call_end` の後に着信の通知が閉じたか、SW の記録の `note`（待った ms、閉じた数）|
|(f) カメラとマイク|`get_user_media` と `rtc_rtp_script_transform` の値|
|(g) 保存の消去の後|消した後に開いた時の `fresh`|

## 3. 記録の置き場

- 結果の JSON は `dev/docs/jp/手順/記録/<試験の番号>/<日付>_<端末>_<OS の版>_<項目>_<回>.json` に置く。
- 置く前に、JSON から Web Push の購読（`subscription`。配信先の URL と鍵を含み、知っている者がその端末へ通知を送れる）を消す。送信の記録（`tools/ios_probe push send --log`）も同じ置き場に置く。
